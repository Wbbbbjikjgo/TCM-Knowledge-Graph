## 项目是什么（一分钟概览）

一句话：**这是一个「中医药版」的智能问答 + 科普内容生成系统。**

它做的事情，从数据进来到答案出去，一共 5 个阶段：

```text
① 采集          ② 抽取          ③ 存储              ④ 检索           ⑤ 生成
原始文本   →   实体+关系三元组  →  Neo4j图库 + FAISS向量 → 三路混合检索  →  多Agent回答/写笔记
(爬虫/PDF/OCR)  (DeepSeek大模型)    (图 + 向量双引擎)     (RRF融合+COROM精排)  (LangGraph编排)
```

核心思路就一句话：**知识图谱（Neo4j）保证答案"有依据"，向量检索（FAISS）保证答案"找得到"，大模型（DeepSeek）负责"说人话"，三者配合杜绝大模型"一本正经地胡说八道"（幻觉）。**

## README.md —— 项目说明书（这里做精炼导读，原文请自行对照）

README 很长（约 500 行），核心信息提炼如下，看完这几条你就抓住了项目的"设计意图"：

1. **背景**：中医药知识"实体多、关系复杂"，传统关键词检索抓不住"辨证论治"的深层逻辑，通用大模型又容易幻觉 → 所以要**知识图谱 + RAG 双引擎**。
2. **三大目标**：知识构建（自动抽取建图谱）、智能问答（图+向量双引擎防幻觉）、内容生成（自动写小红书风格科普）。
3. **关键技术选型理由**（这是理解后续代码的钥匙）：
   - 用 **Neo4j + FAISS 双引擎**：图库擅长关系推理，向量库擅长语义相似，互补。
   - 用 **LangGraph** 而非纯 LangChain：原生支持分支/循环，适合多 Agent 协作。
   - 用 **DeepSeek API**：国产、高性价比、零本地下载。
   - 用 **ModelScope 下国产模型**（达摩院 GTE/COROM）：国内直连，规避 HuggingFace 下载失败。
4. **数据流转**（5 步）与「项目是什么」一节相同。
5. **发布方案**：小红书发布默认走**半自动**（系统预览 → 复制全文 → 粘贴到小红书创作平台），安全无封号风险；自动化接口只留了占位。

> 💡 记住一个贯穿全项目的"暗线"：**模型国产化**。README 第 4 节专门讲了为什么把 HuggingFace 的 `bge-m3`/`bge-reranker` 换成 ModelScope 的达摩院 GTE/COROM——因为国内网络下载 HF 经常失败。后面你会在 `common/embedding.py`、`fusion.py` 里反复看到这条线索。

## configs/agent_config.yaml —— 业务参数总控

这个文件控制「大模型怎么调、检索怎么融合、内容怎么写」。

```yaml
# LLM 配置（DeepSeek，国产 API，零本地下载）
llm:
  model: deepseek-chat        # 可被 DEEPSEEK_MODEL 覆盖
  temperature: 0.3
  max_tokens: 2048

# 混合检索配置
retrieval:
  top_k: 10
  candidate_multiplier: 2     # 各路召回 top_k * 倍数后再融合
  rrf_k: 60                   # RRF 融合常数
  weights:                    # 三路检索参考权重
    graph: 0.4
    vector: 0.3
    keyword: 0.3

# 重排序（达摩院 COROM，ModelScope 下载）
rerank:
  enabled: true
  model: damo/nlp_corom_ranking_chinese-base

# 内容生成（小红书风格）
content:
  platform: xiaohongshu
  max_length: 800
  style:
    - emoji
    - 口语化
    - 话题标签
```

**为什么这么设计（逐块）**：

- `llm.temperature=0.3`：temperature 控制"随机性"，0 是死板、1 是放飞。问答要严谨所以偏低，而生成文案（`content_agent.py`）会单独用 `0.7` 让文字更活泼。
- `retrieval.weights`：三路检索权重 0.4 / 0.3 / 0.3，对应 README 里的混合检索策略。注意这里**只是"参考权重"**，真正生效是在 `fusion.py` 的 RRF 融合里（后面会讲）。
- `candidate_multiplier=2`：每路先召回 `top_k × 2 = 20` 条候选，融合+精排后再截断回 `top_k = 10`。**先广撒网再精选**，避免直接只召回 10 条时好结果漏在排名 11-20。
- `rrf_k=60`：RRF 融合公式里的常数（附录会讲公式）。
- `rerank.enabled=true`：打开 COROM 精排；生产环境如果 GPU 紧张可以关掉，会降级为纯 RRF 顺序（`fusion.py` 里容错）。

## configs/faiss_config.yaml —— 向量索引配置

```yaml
# FAISS 向量索引配置
embedding:
  # 达摩院 GTE 中文向量模型（ModelScope 魔搭社区国内直连下载）
  model: damo/nlp_gte_sentence-embedding_chinese-base
  dim: 768

index:
  type: IndexFlatIP    # 内积相似度（向量归一化后等价余弦相似度）
  normalize: true
  dir: index           # 索引文件输出目录

# 索引集合：与 Neo4j 节点通过 entity_id 关联
collections:
  - name: herb_embeddings
    entity_label: Herb
  - name: formula_embeddings
    entity_label: Fangji
  - name: symptom_embeddings
    entity_label: Symptom
```

**关键点**：

- `dim: 768`：GTE 模型输出 768 维向量。这是"向量维度"，索引和查询必须一致。
- `type: IndexFlatIP`：FAISS 的一种索引类型，`IP` = Inner Product（内积）。因为 `normalize: true`（向量先归一化），内积在数学上等价于余弦相似度，可以理解成"方向越接近、分数越高"。
- `collections` 是**配置驱动**的典型例子：它声明了 3 个向量集合，每个集合对应 Neo4j 里的一种节点标签（`Herb`/`Fangji`/`Symptom`）。`index_builder.py` 和 `retriever.py` 都会读这个列表循环处理——**以后想加"证型集合"，只改这里，代码一行不用动**。

## configs/neo4j_config.yaml —— 图数据库 Schema

```yaml
# Neo4j 图数据库配置（敏感值通过 .env 环境变量注入）
neo4j:
  uri: bolt://localhost:7687        # 可被 NEO4J_URI 覆盖
  user: neo4j                        # 可被 NEO4J_USER 覆盖
  database: neo4j

# 图谱节点标签与索引字段
schema:
  nodes:
    - label: Herb          # 药材
      index_field: name
    - label: Fangji        # 方剂
      index_field: name
    - label: Symptom       # 症状
      index_field: name
    - label: Syndrome      # 证型
      index_field: name
    - label: Effect        # 功效
      index_field: name
    - label: Disease       # 疾病
      index_field: name
  relations:
    - COMPOSED_OF            # (方剂)-[:COMPOSED_OF]->(药材)
    - TREATS                 # (方剂)-[:TREATS]->(证型/疾病)
    - HAS_SYMPTOM            # (证型)-[:HAS_SYMPTOM]->(症状)
    - HAS_EFFECT             # (药材)-[:HAS_EFFECT]->(功效)
    - CONTRAINDICATED_WITH   # (药材)-[:CONTRAINDICATED_WITH]->(药材)
```

**注意一个贯穿全局的设计**：这里节点/关系用的是**英文标签**（`Herb`、`Fangji`、`COMPOSED_OF`），而代码里（`tcm_schema.py`）用的是**中文**（"药材"、"方剂"、"组成"）。

为什么？因为 LLM 用中文抽取更自然（DeepSeek 面对"药材/方剂"比"Herb/Fangji"输出更稳定），而 Neo4j 的 Cypher 语言用英文标签更规范。所以中间需要一张"中文 ↔ 英文"的映射表——这就是下一步 `tcm_schema.py` 干的活。

> ⚠️ 还有个小差异：这里 `relations` 列了 5 种关系，但 `tcm_schema.py` 里定义了 6 种（多了"归经"MERIDIAN_TROPISM）。两者用途不同：这个 YAML 是**给 Cypher 生成器看的 Schema 摘要**，`tcm_schema.py` 是**抽取与校验的权威定义**。这是配置与代码轻微不同步的一个点，读的时候知道即可。

# 第 1 步：common/config.py —— 全项目的地基

> 这是全项目**第一个该看的代码文件**。它几乎被所有模块依赖（`embedding`、`loader`、`retriever`、`fusion`…全都从它这里拿配置）。
> 它不依赖任何本项目内的其他文件——是真正的"根"。

```python
"""统一配置加载：读取 configs/*.yaml，并支持 .env 环境变量覆盖。"""

import os
from functools import lru_cache
from pathlib import Path

import yaml
from dotenv import load_dotenv

PROJECT_ROOT = Path(__file__).resolve().parent.parent
load_dotenv(PROJECT_ROOT / ".env")

# ModelScope 国产模型缓存目录（达摩院 GTE / COROM）
os.environ.setdefault("MODELSCOPE_CACHE", str(PROJECT_ROOT / "models"))


@lru_cache(maxsize=None)
def load_config(name: str) -> dict:
    """加载 configs/ 目录下的 YAML 配置文件。"""
    path = PROJECT_ROOT / "configs" / name
    with open(path, "r", encoding="utf-8") as f:
        return yaml.safe_load(f)


def get_project_root() -> Path:
    return PROJECT_ROOT
```

**逐段讲解**：

1. `PROJECT_ROOT = Path(__file__).resolve().parent.parent`
   - `__file__` 是当前文件路径，`.parent` 取到 `common/`，再 `.parent` 取到项目根。
   - 用"相对自身位置推算根目录"而不是写死绝对路径，**换台电脑、换目录都能跑**，这是工程常识。
2. `load_dotenv(PROJECT_ROOT / ".env")`
   - 把 `.env` 文件里的 `KEY=value` 读进进程环境变量，之后 `os.getenv("DEEPSEEK_API_KEY")` 就能取到。
   - 注意 `load_dotenv` 默认**不覆盖**已存在的环境变量，所以"真实环境变量 > .env 文件"。
3. `os.environ.setdefault("MODELSCOPE_CACHE", ...)`
   - `setdefault` 意思是"如果没设过才设"。目的：让 ModelScope 把模型权重下载到项目的 `models/` 目录，而不是默认的用户目录——**让模型跟着项目走**，方便 Docker 挂载（见 docker-compose 里的 `model_cache` 卷）。
4. `@lru_cache(maxsize=None)` 装饰器
   - **缓存**：同一个 YAML 文件只会被读盘解析一次，之后直接返回内存里的结果。
   - 为什么重要？后面你会看到 `load_config("agent_config.yaml")` 在 `fusion.py` 等模块里被反复调用，每次读盘会又慢又浪费。这是"单例思想"的轻量版（配置天然只读、可安全缓存）。
5. `yaml.safe_load`（而不是 `yaml.load`）
   - `safe_load` 只解析纯数据，不执行任意 Python 对象——**防 YAML 注入**的安全做法。

# 第 2 步：common/llm.py —— 大模型工厂

> "工厂"（Factory）是设计模式的名字：**不直接 `new` 对象，而是提供一个函数，调用它就得到一个配置好的对象**。
> 全项目所有用到 DeepSeek 的地方都调 `get_llm()`，保证"创建 LLM 的逻辑只有一处"。

```python
"""DeepSeek LLM 工厂：API 形式接入，国产模型零本地下载。"""

import os

from langchain_openai import ChatOpenAI


def get_llm(temperature: float = 0.3, model: str | None = None) -> ChatOpenAI:
    """创建 DeepSeek Chat 客户端（兼容 OpenAI 协议）。"""
    return ChatOpenAI(
        model=model or os.getenv("DEEPSEEK_MODEL", "deepseek-chat"),
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url=os.getenv("DEEPSEEK_BASE_URL", "https://api.deepseek.com"),
        temperature=temperature,
    )
```

**逐段讲解**：

1. **为什么用 `ChatOpenAI` 调 DeepSeek？**
   - DeepSeek 的 API **兼容 OpenAI 协议**（URL 结构、请求/响应格式一样），所以 LangChain 里现成的 `ChatOpenAI` 客户端把 `base_url` 指向 DeepSeek 就能直接用，不用单独装 DeepSeek 的 SDK。
2. `model or os.getenv("DEEPSEEK_MODEL", "deepseek-chat")`
   - 优先级：**调用时传入的 model 参数 > 环境变量 > 硬编码默认值**。这叫做"配置覆盖链"，和 `common/config.py` 里的设计一脉相承。
3. `temperature: float = 0.3` 默认值
   - 后面你会看到：抽取、Cypher 生成、问答用 `get_llm(temperature=0)`（要严谨），写小红书文案用 `get_llm(temperature=0.7)`（要活泼）。**同一个工厂，不同参数，产出不同性格的模型**。

# 第 3 步：kg/schema/tcm_schema.py —— 图谱的"宪法"

> Schema（模式）就是**数据的合法规则**：哪些实体类型、哪些关系类型、哪些组合是合法的。
> 全项目所有抽取、校验、入库都以此为准。把它放在抽取器前面看，因为抽取器要 import 它。

```python
"""中医药知识图谱 Schema 定义。"""

# 实体类型（中文）→ Neo4j 节点标签
ENTITY_LABEL_MAP = {
    "药材": "Herb",
    "方剂": "Fangji",
    "症状": "Symptom",
    "证型": "Syndrome",
    "功效": "Effect",
    "疾病": "Disease",
}

ENTITY_TYPES = list(ENTITY_LABEL_MAP.keys())

# 关系类型（中文）→ Neo4j 关系类型
RELATION_TYPE_MAP = {
    "主治": "TREATS",                    # (方剂)->(证型/疾病)
    "组成": "COMPOSED_OF",               # (方剂)->(药材)
    "功效": "HAS_EFFECT",                # (药材)->(功效)
    "禁忌": "CONTRAINDICATED_WITH",      # (药材)->(药材/证型)
    "归经": "MERIDIAN_TROPISM",          # (药材)->(经络)
    "对应症状": "HAS_SYMPTOM",           # (证型)->(症状)
}

RELATION_TYPES = list(RELATION_TYPE_MAP.keys())

# 关系合法性约束：(头实体类型, 关系, 尾实体类型) 允许的组合
VALID_TRIPLE_PATTERNS = {
    ("方剂", "主治", "证型"),
    ("方剂", "主治", "疾病"),
    ("方剂", "组成", "药材"),
    ("药材", "功效", "功效"),
    ("药材", "禁忌", "药材"),
    ("证型", "对应症状", "症状"),
    ("疾病", "对应症状", "症状"),
}
```

**逐段讲解**：

1. **两张"中↔英"映射表**：`ENTITY_LABEL_MAP` 和 `RELATION_TYPE_MAP`。
   - 这就是第 0 步预告的那张"翻译表"——LLM 用中文抽取，Neo4j 用英文标签存储，这里负责互译。
   - `ENTITY_TYPES = list(ENTITY_LABEL_MAP.keys())` 顺手生成"中文类型列表"，供提示词模板使用（下一章你会看到它被格式化进 Prompt）。
2. **`VALID_TRIPLE_PATTERNS` 是精华**——它定义了"什么三元组算合法"。
   - 每个元素是 `(头实体类型, 关系, 尾实体类型)` 三元组。
   - 例如 `("方剂", "组成", "药材")` 表示"方剂-组成-药材"合法；反过来 `("药材", "组成", "方剂")` 就**不合法**（药材不能"组成"方剂，逻辑上反了）。
   - 它的作用在 `validator.py`（第 6 步）会大显身手：过滤掉 LLM 抽错方向的脏数据。
3. **注意两个细节**：
   - `("药材", "功效", "功效")` 头尾都是"功效"类型？这里的语义是"药材-有功效-某种功效"，头实体是"药材"，尾实体是"功效"实体（功效本身也是一种实体，比如"疏肝解郁"作为一个 `Effect` 节点）。
   - "归经" `MERIDIAN_TROPISM` 在 `VALID_TRIPLE_PATTERNS` 里**没有对应的合法组合**（因为"经络"实体类型没定义）——意味着"归经"关系能被识别、能映射，但实际三元组会被校验器过滤。这是项目未完全实现的一个小留白。

# 第 4 步：kg/entity_extraction/prompt_templates.py —— 抽取提示词

> Prompt（提示词）就是"给大模型下达指令的文字"。这个文件把抽取任务的指令写成模板，**和数据/代码分离**，方便单独调优。

```python
"""实体与关系抽取 Prompt 模板。"""

EXTRACTION_SYSTEM_PROMPT = """你是中医药领域的知识图谱构建专家。请从给定文本中抽取实体与关系三元组。

规则：
1. 实体类型只能是：{entity_types}
2. 关系类型只能是：{relation_types}
3. 实体名称使用规范名称，去除多余修饰（如"去核山茱萸"记为"山茱萸"需谨慎，保留原文关键信息）

5. 三元组必须语义完整：(头实体, 关系, 尾实体)

EXTRACTION_FEW_SHOT = """示例输入：

- {{"entity_type": "症状", "entity_name": "胸闷"}}

```

**逐段讲解**：

1. **`{entity_types}` 和 `{relation_types}` 是占位符**——它们在 `extractor.py` 里用 `.format()` 填充（把第 3 步的 `ENTITY_TYPES`/`RELATION_TYPES` 塞进来）。这样 Prompt 里的类型清单**永远和代码里的 Schema 同步**，不会出现"代码加了新类型、Prompt 还写死旧类型"的 bug。
2. **`EXTRACTION_FEW_SHOT` 是"少样本示例"（Few-shot）**：
   - 给模型看一个"输入→期望输出"的样板，模型会模仿它的格式。
   - 注意示例里的大括号是 **双括号 `{{` `}}`**！因为整段字符串之后要过 `.format()`，双括号会被转义成单括号输出。这是 Python `.format()` 的经典坑，没写对会直接报错。
3. **Prompt 里的"规则 4：只抽取明确表述，禁止臆测"**——这是**防幻觉**的第一道闸门：让模型只抽文中确实写的，不脑补。这个思想贯穿全项目（问答 Prompt 也反复强调"仅依据参考资料"）。

> 为什么把 Prompt 单独放一个文件而不是写死在代码里？——**关注点分离**。提示词工程师可以只改这个文件调效果，不动 Python 逻辑；代码里 import 的是"值"而不是"字符串字面量"。

# 第 5 步：kg/entity_extraction/extractor.py —— 实体/关系抽取器

> 这是"从文本里扒出知识"的核心。它把前面几章串起来：用 `get_llm()` 调模型、用 `prompt_templates` 的提示词、用 `kg.schema` 的类型清单。
> 这里你会第一次见到 **Pydantic 模型 + LangChain 结构化输出**这个组合技。

```python
"""实体与关系抽取器：DeepSeek 结构化输出（实体 + 关系三元组）。"""

from pydantic import BaseModel, Field

from common.llm import get_llm
from kg.entity_extraction.prompt_templates import (
    EXTRACTION_FEW_SHOT,
    EXTRACTION_SYSTEM_PROMPT,
)
from kg.schema import ENTITY_TYPES, RELATION_TYPES


class Entity(BaseModel):
    entity_type: str = Field(description=f"实体类型，只能是{ENTITY_TYPES}之一")
    entity_name: str = Field(description="实体规范名称")


class Triple(BaseModel):
    head: str = Field(description="头实体名称")
    relation: str = Field(description=f"关系类型，只能是{RELATION_TYPES}之一")
    tail: str = Field(description="尾实体名称")


class ExtractionResult(BaseModel):
    entities: list[Entity] = Field(default_factory=list)
    triples: list[Triple] = Field(default_factory=list)


class EntityRelationExtractor:
    """基于 DeepSeek 结构化输出的实体与关系联合抽取器。"""

    def __init__(self):
        self.chain = get_llm(temperature=0).with_structured_output(ExtractionResult)
        self.system_prompt = EXTRACTION_SYSTEM_PROMPT.format(
            entity_types="、".join(ENTITY_TYPES),
            relation_types="、".join(RELATION_TYPES),
        )

    def extract(self, text: str) -> ExtractionResult:
        """从单段文本抽取实体与三元组。"""
        text = text.strip()
        if not text:
            return ExtractionResult()
        messages = [
            ("system", self.system_prompt + "\n" + EXTRACTION_FEW_SHOT),
            ("human", text),
        ]
        return self.chain.invoke(messages)

    def extract_document(self, doc: dict, chunk_size: int = 800) -> ExtractionResult:
        """对 parse_file 输出的结构化文档逐块抽取并合并去重。"""
        merged = ExtractionResult()
        seen_entities, seen_triples = set(), set()

        for section in doc.get("sections", []):
            for chunk in _split_chunks(section.get("content", ""), chunk_size):
                result = self.extract(chunk)
                for e in result.entities:
                    key = (e.entity_type, e.entity_name)
                    if key not in seen_entities:
                        seen_entities.add(key)
                        merged.entities.append(e)
                for t in result.triples:
                    key = (t.head, t.relation, t.tail)
                    if key not in seen_triples:
                        seen_triples.add(key)
                        merged.triples.append(t)
        return merged


def _split_chunks(text: str, chunk_size: int) -> list[str]:
    """按段落边界切分长文本，避免超出模型上下文。"""
    paragraphs = [p.strip() for p in text.split("\n") if p.strip()]
    chunks, buf = [], ""
    for p in paragraphs:
        if len(buf) + len(p) > chunk_size and buf:
            chunks.append(buf)
            buf = p
        else:
            buf = buf + "\n" + p if buf else p
    if buf:
        chunks.append(buf)
    return chunks or ([text] if text else [])
```

**逐段讲解**：

1. **Pydantic `BaseModel` 定义数据结构**（`Entity`/`Triple`/`ExtractionResult`）
   - Pydantic 是 Python 的"数据校验库"：定义字段名+类型，自动做类型校验和序列化。
   - `Field(description=...)` 里的描述**不是给人看的，是给大模型看的**！配合下面的 `with_structured_output`，这些 description 会变成 LLM 输出的约束。
   - `default_factory=list` 而不是 `=[]`：**Python 的可变默认参数陷阱**——`=[]` 会让所有实例共享同一个 list，`default_factory` 每次调用才新建一个，安全。
2. **`with_structured_output(ExtractionResult)`** —— 这是全项目的"灵魂组合技"：
   - LangChain 会把 Pydantic 模型转成"函数调用/JSON Schema"约束，让 DeepSeek **保证返回符合结构的 JSON**（而不是自由文本）。
   - 这就是为什么后面能放心地 `result.entities`、`result.triples` 直接取——**结构是强制的**。
   - 对比 README 里老式的 `create_extraction_chain`，这是 LangChain 更现代的写法。
3. **`get_llm(temperature=0)`**：抽取要绝对稳定，所以温度设为 0（确定性最高）。
4. **`extract_document` 的"分块 + 去重"设计**：
   - `_split_chunks` 按**段落**切块（不是按字符硬切），因为硬切会把一句话劈成两半导致抽取失败。它尽量把段落填满到 `chunk_size=800` 字再换块。
   - 逐块抽取后用 `seen_entities`/`seen_triples` 两个 `set` 去重——同一个实体在多个块里重复出现时只保留一份。
5. **为什么 `extract` 要处理空文本**：`text.strip()` 后为空直接返回空结果，避免把空字符串发给 LLM 浪费调用。

# 第 6 步：kg/relation_extraction/validator.py —— 三元组校验

> 大模型会抽错（类型瞎编、关系方向反了、实体没定义）。这个文件用 `tcm_schema.py` 里的规则给抽取结果"过筛子"。
> 它是知识质量的**第二道闸门**（第一道是 Prompt 里的"禁止臆测"）。

```python
"""关系抽取后处理：基于图谱 Schema 的规则校验与过滤。"""

from kg.entity_extraction.extractor import Entity, ExtractionResult
from kg.schema import ENTITY_TYPES, RELATION_TYPES, VALID_TRIPLE_PATTERNS


def validate_extraction(result: ExtractionResult) -> ExtractionResult:
    """过滤非法实体类型/关系类型，按模式约束校验三元组，
    并对缺失类型的头尾实体尝试依据关系模式推断类型。"""
    entity_type_of = {}
    valid_entities = []
    for e in result.entities:
        if e.entity_type in ENTITY_TYPES and e.entity_name.strip():
            valid_entities.append(e)
            entity_type_of[e.entity_name] = e.entity_type

    def infer_type(name: str, patterns: list[tuple], pos: int) -> str | None:
        """在模式唯一时推断实体类型，并补充实体记录。"""
        candidates = {p[pos] for p in patterns}
        if len(candidates) == 1:
            etype = candidates.pop()
            entity_type_of[name] = etype
            valid_entities.append(Entity(entity_type=etype, entity_name=name))
            return etype
        return None

    valid_triples = []
    for t in result.triples:
        if t.relation not in RELATION_TYPES or t.head == t.tail:
            continue
        patterns = [p for p in VALID_TRIPLE_PATTERNS if p[1] == t.relation]
        head_type = entity_type_of.get(t.head) or infer_type(t.head, patterns, 0)
        tail_type = entity_type_of.get(t.tail) or infer_type(t.tail, patterns, 2)
        # 头尾实体必须可确定类型，且三元组模式符合 Schema 约束
        if head_type and tail_type and (head_type, t.relation, tail_type) in patterns:
            valid_triples.append(t)

    return ExtractionResult(entities=valid_entities, triples=valid_triples)
```

**逐段讲解**：

1. **第一轮过滤（实体）**：
   - `e.entity_type in ENTITY_TYPES`：扔掉类型不在 6 类里的实体（比如模型瞎编了个"部位"类型）。
   - `e.entity_name.strip()`：扔掉空名字。
   - `entity_type_of` 是个字典 `{实体名: 类型}`，方便后面三元组反查类型。
2. **`infer_type` —— 类型推断**：
   - 有些三元组的头/尾实体没在 entities 列表里出现（模型漏抽了实体），这里尝试从关系模式反推它的类型。
   - `candidates = {p[pos] for p in patterns}`：对"组成"关系，合法模式只有 `("方剂","组成","药材")`，那么 pos=0（头）只可能是"方剂"、pos=2（尾）只可能是"药材"——**唯一时**就能确定。
   - 如果候选不唯一（歧义），返回 `None`，宁可丢弃也不乱猜——**宁可漏不可错**。
3. **第二轮过滤（三元组）**：
   - `t.relation not in RELATION_TYPES`：关系类型非法，丢。
   - `t.head == t.tail`：自己连自己（"柴胡 组成 柴胡"），无意义，丢。
   - `(head_type, t.relation, tail_type) in patterns`：**最终裁决**——头尾类型+关系是否符合 Schema 允许的组合。这一步能拦下"药材-组成-方剂"这种方向颠倒的脏数据。
4. **设计思想总结**：这条流水线叫 **"规则过滤 + 类型推断"**，是对 LLM 输出的"后处理护栏"。它不依赖 LLM，速度快、可解释、永不幻觉。

# 第 7 步：common/embedding.py —— 向量服务（单例）

> 把文字变成"能算相似度"的数字向量，是 RAG 的基石。这个文件用**单例模式**管理达摩院 GTE 模型，
> 因为模型加载很慢、很占内存——**全项目只加载一次，大家共享**。

```python
"""达摩院 GTE 中文向量服务：经 ModelScope 魔搭社区下载，国内直连。"""

import numpy as np

from common.config import load_config


class EmbeddingService:
    """单例向量编码器：damo/nlp_gte_sentence-embedding_chinese-base（768维）。"""

    _instance: "EmbeddingService | None" = None

    def __init__(self):
        from modelscope import snapshot_download
        from sentence_transformers import SentenceTransformer

        cfg = load_config("faiss_config.yaml")["embedding"]
        # 首次运行自动从魔搭社区下载模型权重，之后直接读本地缓存
        local_dir = snapshot_download(cfg["model"])
        self.model = SentenceTransformer(local_dir)
        self.dim = cfg["dim"]

    @classmethod
    def get_instance(cls) -> "EmbeddingService":
        if cls._instance is None:
            cls._instance = cls()
        return cls._instance

    def encode(self, texts: list[str], batch_size: int = 32) -> np.ndarray:
        """批量编码并 L2 归一化（归一化后内积 == 余弦相似度）。"""
        if isinstance(texts, str):
            texts = [texts]
        vectors = self.model.encode(
            texts, batch_size=batch_size, normalize_embeddings=True,
            show_progress_bar=False,
        )
        return np.asarray(vectors, dtype="float32")
```

**逐段讲解**：

1. **单例模式（Singleton）怎么实现的**：
   - 类属性 `_instance` 存"唯一的那个实例"，初始为 `None`。
   - `get_instance()` 是**类方法**（`@classmethod`）：第一次调用时 `_instance is None` → 新建并缓存；之后每次都直接返回缓存的实例。
   - 好处：模型（几百 MB）只在进程里加载一次。后面 `retriever.py`、`index_builder.py` 都调 `EmbeddingService.get_instance()`，不会重复加载。
2. **模型从哪里来（ModelScope 路线）**：
   - `snapshot_download(cfg["model"])`：从魔搭社区下载模型到本地缓存（第 1 步设好的 `MODELSCOPE_CACHE` 目录），返回本地路径。
   - `SentenceTransformer(local_dir)`：用 sentence-transformers 加载并准备推理。
   - 为什么 import 放在函数内而不是文件顶部？——**延迟导入**。这样"不调用向量功能就不必装/加载这些重依赖"，启动更快、更解耦。
3. **`normalize_embeddings=True` + `float32`**：
   - 向量归一化后，两个向量的内积 = 余弦相似度（方向一致性）。这就是 `faiss_config.yaml` 里 `IndexFlatIP`（内积索引）能当"余弦相似度"用的前提。
   - `float32`：FAISS 要求 float32，也省一半内存（相比 float64）。
4. **`encode` 的容错**：`isinstance(texts, str)` 时自动包成列表——调用方传单条字符串也不会崩。
5. **`batch_size=32`**：批量编码比逐条编码快很多（GPU/CPU 都能并行）。

# 第 8 步：kg/neo4j_loader/loader.py —— 图谱入库

> 把第 5 步抽取、第 6 步校验后的三元组，真正写进 Neo4j 图数据库。
> 这里你会学到：Neo4j 的 **MERGE**（幂等写入）、**参数化查询**（防注入）、以及"索引"的作用。

```python
"""Neo4j 知识图谱批量写入：索引构建、节点/关系 MERGE、CLI 入口。"""

import argparse
import os

from neo4j import GraphDatabase

from common.config import load_config
from kg.entity_extraction.extractor import Entity, ExtractionResult, Triple
from kg.schema import ENTITY_LABEL_MAP, RELATION_TYPE_MAP


def get_driver():
    """创建 Neo4j 驱动（连接信息来自 .env）。"""
    return GraphDatabase.driver(
        os.getenv("NEO4J_URI", "bolt://localhost:7687"),
        auth=(os.getenv("NEO4J_USER", "neo4j"), os.getenv("NEO4J_PASSWORD", "")),
    )


class KnowledgeGraphLoader:
    """将抽取结果写入 Neo4j，构建中医药知识图谱。"""

    def __init__(self, driver=None):
        self.driver = driver or get_driver()

    def ensure_schema(self):
        """按配置为各节点标签的 name 字段创建索引。"""
        cfg = load_config("neo4j_config.yaml")["schema"]
        with self.driver.session() as session:
            for node in cfg["nodes"]:
                session.run(
                    f"CREATE INDEX {node['label'].lower()}_{node['index_field']}_idx IF NOT EXISTS "
                    f"FOR (n:{node['label']}) ON (n.{node['index_field']})"
                )

    def load(self, result: ExtractionResult) -> dict:
        """批量写入实体节点与关系三元组，返回写入统计。"""
        entity_type_of = {e.entity_name: e.entity_type for e in result.entities}
        node_count = self._merge_nodes(result.entities)
        rel_count = self._merge_relations(result.triples, entity_type_of)
        return {"nodes": node_count, "relations": rel_count}

    def _merge_nodes(self, entities: list[Entity]) -> int:
        by_label: dict[str, list[str]] = {}
        for e in entities:
            label = ENTITY_LABEL_MAP.get(e.entity_type)
            if label:
                by_label.setdefault(label, []).append(e.entity_name)

        count = 0
        with self.driver.session() as session:
            for label, names in by_label.items():
                # 标签来自受控 Schema 映射，无注入风险
                session.run(
                    f"UNWIND $names AS name MERGE (n:{label} {{name: name}})",
                    names=list(dict.fromkeys(names)),
                )
                count += len(set(names))
        return count

    def _merge_relations(self, triples: list[Triple], entity_type_of: dict) -> int:
        count = 0
        with self.driver.session() as session:
            for t in triples:
                head_label = ENTITY_LABEL_MAP.get(entity_type_of.get(t.head, ""))
                tail_label = ENTITY_LABEL_MAP.get(entity_type_of.get(t.tail, ""))
                rel_type = RELATION_TYPE_MAP.get(t.relation)
                if not (head_label and tail_label and rel_type):
                    continue
                session.run(
                    f"MATCH (a:{head_label} {{name: $head}}) "
                    f"MATCH (b:{tail_label} {{name: $tail}}) "
                    f"MERGE (a)-[:{rel_type}]->(b)",
                    head=t.head,
                    tail=t.tail,
                )
                count += 1
        return count

    def close(self):
        self.driver.close()


def _demo_result() -> ExtractionResult:
    """演示数据：柴胡疏肝散示例三元组。"""
    entities = [
        Entity(entity_type="方剂", entity_name="柴胡疏肝散"),
        Entity(entity_type="药材", entity_name="柴胡"),
        Entity(entity_type="药材", entity_name="香附"),
        Entity(entity_type="证型", entity_name="肝郁气滞证"),
    ]
    triples = [
        Triple(head="柴胡疏肝散", relation="组成", tail="柴胡"),
        Triple(head="柴胡疏肝散", relation="组成", tail="香附"),
        Triple(head="柴胡疏肝散", relation="主治", tail="肝郁气滞证"),
    ]
    return ExtractionResult(entities=entities, triples=triples)


if __name__ == "__main__":
    parser = argparse.ArgumentParser(description="Neo4j 知识图谱导入")
    parser.add_argument("--demo", action="store_true", help="导入柴胡疏肝散示例数据")
    args = parser.parse_args()

    loader = KnowledgeGraphLoader()
    try:
        loader.ensure_schema()
        if args.demo:
            stats = loader.load(_demo_result())
            print(f"演示数据写入完成: {stats}")
        else:
            print("请通过 KnowledgeGraphLoader.load() 传入抽取结果，或使用 --demo")
    finally:
        loader.close()
```

**逐段讲解**：

1. **`get_driver()` —— 连接工厂**：从环境变量读 Neo4j 地址和账号（`.env`），返回驱动对象。`driver` 是 Neo4j 官方驱动的"长连接句柄"，一个进程通常一个就够了。
2. **`ensure_schema()` —— 建索引**：
   - 为每个节点标签的 `name` 字段建索引（如 `herb_name_idx`）。
   - `IF NOT EXISTS` 保证幂等（重复执行不报错）。
   - 为什么重要：后面 `MATCH (n:Herb {name: $name})` 这种按名字查节点的操作，有索引是**毫秒级**，没索引要**全库扫描**。
3. **`_merge_nodes` —— 批量建节点**：
   - 先按标签分组（`by_label`），再每条 Cypher 批量处理一个标签的所有名字。
   - `MERGE` 是 Neo4j 的"**存在则匹配、不存在则创建**"语句——天然幂等，重复导入不会产生重复节点。
   - `UNWIND $names AS name` + `names=list(dict.fromkeys(names))`：用**参数化查询**传值并去重。`dict.fromkeys` 去重是保持顺序的 Python 惯用法。
   - 注释明确写了"标签来自受控 Schema 映射，无注入风险"——因为标签名是从 `ENTITY_LABEL_MAP` 来的**白名单值**，不是用户输入，所以可以放心拼进 Cypher 字符串；而名字是用户数据，必须走 `$names` 参数化。
4. **`_merge_relations` —— 批量建关系**：
   - 先查中文→英文映射，映射不上（比如"归经"没实现）就 `continue` 跳过。
   - `MATCH (a:标签 {name: $head}) MATCH (b:标签 {name: $tail}) MERGE (a)-[:关系]->(b)`：**找到两端节点，再连一条关系**。
   - 关键安全点：`head`/`tail` 是**参数化**传入（`$head`/`$tail`），绝不拼字符串——否则中文名里的特殊字符会导致 Cypher 注入或语法错误（这正是 AGENTS.md 里提过的"中文转义问题"）。
5. **`__main__` 入口**：`argparse` 提供命令行 `python -m kg.neo4j_loader.loader --demo`，用 `try/finally` 保证无论如何 `close()` 连接。
   - `_demo_result()` 是一个"麻雀虽小五脏俱全"的最小示例（柴胡疏肝散 + 2 味药 + 1 证型）。

```python
    "牛膝": ["逐瘀通经", "补肝肾", "强筋骨", "引血下行"],
    "桔梗": ["宣肺", "利咽", "祛痰", "排脓"],
}
```

**说明**：`HERB_EFFECTS` 是"药材 → 功效列表"的映射，共 32 味药。它补充了 `FORMULAS` 里没有的"药材-功效"关系。

```python
def build_extraction_result() -> ExtractionResult:
    """从演示数据构建 ExtractionResult。"""
    entities = []
    triples = []
    seen_entities = set()
    seen_triples = set()

    def add_entity(entity_type: str, entity_name: str):
        key = (entity_type, entity_name)
        if key not in seen_entities:
            seen_entities.add(key)
            entities.append(Entity(entity_type=entity_type, entity_name=entity_name))

    def add_triple(head: str, relation: str, tail: str):
        key = (head, relation, tail)
        if key not in seen_triples:
            seen_triples.add(key)
            triples.append(Triple(head=head, relation=relation, tail=tail))

    # 处理每个方剂
    for formula in FORMULAS:
        fname = formula["name"]
        add_entity("方剂", fname)

        # 方剂 -> 组成 -> 药材
        for herb in formula["herbs"]:
            add_entity("药材", herb)
            add_triple(fname, "组成", herb)

        # 方剂 -> 主治 -> 证型
        syndrome = formula["syndrome"]
        add_entity("证型", syndrome)
        add_triple(fname, "主治", syndrome)

        # 证型 -> 对应症状 -> 症状
        for symptom in formula["symptoms"]:
            add_entity("症状", symptom)
            add_triple(syndrome, "对应症状", symptom)

    # 药材 -> 功效 -> 功效
    for herb, effects in HERB_EFFECTS.items():
        add_entity("药材", herb)
        for effect in effects:
            add_entity("功效", effect)
            add_triple(herb, "功效", effect)

    return ExtractionResult(entities=entities, triples=triples)


def import_demo_data():
    """导入演示数据到 Neo4j。"""
    loader = KnowledgeGraphLoader()
    try:
        loader.ensure_schema()
        result = build_extraction_result()
        stats = loader.load(result)
        print(f"[OK] 演示数据导入完成：{stats['nodes']} 个节点，{stats['relations']} 条关系")
        print(f"   - 方剂：{len(FORMULAS)} 个")
        print(f"   - 药材：{len(HERB_EFFECTS)} 个")
        print(f"   - 证型：{len(set(f['syndrome'] for f in FORMULAS))} 个")
        print(f"   - 症状：{len(set(s for f in FORMULAS for s in f['symptoms']))} 个")
        print(f"   - 功效：{len(set(e for effects in HERB_EFFECTS.values() for e in effects))} 个")
    finally:
        loader.close()


if __name__ == "__main__":
    import_demo_data()
```

**逐段讲解**：

1. **数据结构设计**：`FORMULAS`（方剂列表）和 `HERB_EFFECTS`（药材→功效字典）用**可读性极好的纯 Python 字面量**描述中医药知识，非程序员也能看懂和增删。
2. **`build_extraction_result()` 的两个闭包**：
   - `add_entity`/`add_triple` 是函数内定义的辅助函数（闭包），内部用 `seen_*` 集合去重——**复用了第 5 步 extractor 的去重思想**。
   - 遍历逻辑把"方剂→药材（组成）、方剂→证型（主治）、证型→症状（对应症状）、药材→功效（功效）"这 4 类关系填进去，正好对应 `tcm_schema.py` 的合法模式。
3. **为什么造 `ExtractionResult` 而不是直接写库**：
   - 这是**关键抽象**。无论数据来自大模型抽取（`extractor.py`）还是手工演示数据，最终都是 `ExtractionResult`，下游 `loader.load()`、`validator` 全都不用改。
   - 等价于"统一货币"思想：不同来源的数据都换成同一种格式再消费。
4. **`import_demo_data()`**：完整走一遍 `ensure_schema() → build → load`，并在 `finally` 里关闭连接。打印统计用 `set()` 去重计数。
5. **`__main__` 入口**：`python -m kg.demo_data` 直接导数据。

## data/crawler/spiders/tcm_spider.py —— 爬虫骨架

```python
"""通用中医药文献采集 Spider（按目标站点定制选择器）。

这个爬虫用于从中医药文献网站采集文章数据。
使用前需要根据目标网站的DOM结构调整CSS选择器。
"""

# 导入日期时间模块，用于记录爬取时间
from datetime import datetime

# 导入Scrapy框架的核心模块
import scrapy

# 从当前目录的items模块导入TcmDocItem数据容器
# TcmDocItem定义了采集数据的结构：source(来源), title(标题), content(内容)等
from data.crawler.items import TcmDocItem


class TcmSpider(scrapy.Spider):
    """定向爬虫骨架：将 start_urls 指向目标中医药文献站点，
    并按站点 DOM 结构调整 parse 中的 CSS 选择器。
    
    使用说明：
    1. 修改 start_urls 为实际的中医药文献网站URL
    2. 修改 allowed_domains 为网站域名
    3. 调整 parse() 中的列表页选择器
    4. 调整 parse_detail() 中的详情页选择器
    """
    
    # ==================== 爬虫基本配置 ====================
    
    # 爬虫名称，用于命令行启动：scrapy crawl tcm
    name = "tcm"
    
    # 起始URL列表，爬虫从这里开始抓取
    # 示例入口，部署时替换为实际数据源
    # 例子：["https://www.zysj.com.cn/"] 或 ["https://www.dayi.org.cn/"]
    start_urls = ["https://example.com/tcm/articles"]
    
    # 允许爬取的域名白名单，防止爬虫爬到外部网站
    # 例子：["zysj.com.cn"] 或 ["dayi.org.cn"]
    allowed_domains = ["example.com"]
    
    # ==================== 自定义爬虫设置 ====================
    
    custom_settings = {
        # 下载延迟：每次请求间隔1秒，避免对目标站点造成过大压力
        # 这是礼貌爬取的基本要求，防止IP被封
        "DOWNLOAD_DELAY": 1.0,  # 单位：秒
        
        # 遵守网站的robots.txt协议
        # 如果目标网站的robots.txt禁止爬取，Scrapy会停止请求
        "ROBOTSTXT_OBEY": True,
    }
    
    # ==================== 列表页解析方法 ====================
    
    def parse(self, response):
        """解析文章列表页，提取详情页链接和翻页链接。
        
        参数:
            response: Scrapy的响应对象，包含下载的HTML内容
            
        工作流程:
            1. 从列表页提取所有文章详情页的链接
            2. 对每个链接发起详情页请求
            3. 提取翻页链接，继续爬取下一页
        """
        
        # ----- 第一步：提取详情页链接 -----
        # 使用CSS选择器提取所有文章链接的href属性
        # 选择器说明：选择所有class为"article-link"的<a>标签，提取其href属性
        # 例子：如果HTML是 <a class="article-link" href="/article/123.html">文章标题</a>
        # 则会提取出 "/article/123.html"
        # 
        # getall() 返回所有匹配结果的列表
        # 如果匹配不到，返回空列表
        for href in response.css("a.article-link::attr(href)").getall():
            # 使用response.follow构造完整的URL并发起请求
            # 参数：href可以是相对路径或绝对路径
            # callback=self.parse_detail 指定用parse_detail方法处理响应
            # 这样每个详情页都会调用parse_detail进行解析
            yield response.follow(href, callback=self.parse_detail)
        
        # ----- 第二步：提取翻页链接 -----
        # 使用CSS选择器提取"下一页"链接
        # 选择器说明：选择class为"next-page"的<a>标签，提取其href属性
        # 例子：<a class="next-page" href="/articles/page/2">下一页</a>
        next_page = response.css("a.next-page::attr(href)").get()
        
        # 如果存在翻页链接，继续爬取下一页
        if next_page:
            # 发起翻页请求，callback指向自身（parse方法）
            # 这样就实现了递归翻页，直到没有下一页为止
            yield response.follow(next_page, callback=self.parse)
    
    # ==================== 详情页解析方法 ====================
    
    def parse_detail(self, response):
        """解析文章详情页，提取标题、内容等结构化信息。
        
        参数:
            response: 详情页的响应对象
            
        返回:
            TcmDocItem: 包含提取数据的Item对象
            
        示例HTML结构：
            <h1>麻黄汤的临床应用</h1>
            <div class="content">
                <p>麻黄汤由麻黄、桂枝、杏仁、甘草组成。</p>
                <p>具有发汗解表，宣肺平喘的功效。</p>
            </div>
        """
        
        # ----- 第一步：创建数据容器 -----
        # 实例化TcmDocItem，这是一个类似字典的对象
        # 用于存储采集到的数据
        item = TcmDocItem()
        
        # ----- 第二步：提取数据字段 -----
        
        # 提取来源URL：当前页面的完整URL
        # response.url 包含协议、域名、路径等完整信息
        # 例子：https://example.com/article/123.html
        item["source"] = response.url
        
        # 提取文章标题
        # 选择器说明：选择<h1>标签的文本内容
        # get(default="") 获取第一个匹配结果，如果不存在返回空字符串
        # .strip() 去除首尾空白字符
        # 例子：<h1>麻黄汤的临床应用</h1> -> "麻黄汤的临床应用"
        item["title"] = response.css("h1::text").get(default="").strip()
        
        # 预留section字段（可存储章节信息，当前为空字符串）
        # 有些网站可能有章节划分，这里保留字段以备扩展
        item["section"] = ""
        
        # 提取文章正文内容
        # 步骤说明：
        # 1. response.css("div.content p::text") 选择class="content"的div下的所有p标签的文本
        # 2. getall() 获取所有匹配的文本列表
        # 3. 对每个文本进行.strip()去除首尾空白
        # 4. 用换行符"\n"连接所有段落
        # 5. 最后整体.strip()去除首尾空白
        # 
        # 例子：
        # HTML: <div class="content">
        #          <p>第一段内容</p>
        #          <p>第二段内容</p>
        #       </div>
        # 结果: "第一段内容\n第二段内容"
        item["content"] = "\n".join(
            p.strip() for p in response.css("div.content p::text").getall()
        ).strip()
        
        # 记录爬取时间
        # datetime.now() 获取当前时间
        # .isoformat() 转换为ISO格式字符串：2024-01-15T10:30:00
        # 便于后续数据处理和追溯
        item["crawl_time"] = datetime.now().isoformat()
        
        # ----- 第三步：验证并输出数据 -----
        # 检查content是否有内容（非空）
        # 如果content为空，说明可能页面结构不对或没有正文
        # 此时不yield item，避免保存空数据
        if item["content"]:
            # yield将数据传递给Scrapy的Pipeline进行后续处理
            # Pipeline可以保存到文件、数据库等
            yield item
```

**逐段讲解**：

1. **`name = "tcm"`**：爬虫的唯一标识，启动命令是 `scrapy crawl tcm`。
2. **`start_urls` + `allowed_domains`**：起始 URL 列表 + 允许爬的域名白名单。这里写的是 `example.com` **占位**，注释说明"部署时替换为实际数据源"——爬虫是"骨架"，具体站点要现场定制。
3. **`custom_settings`**：
   - `DOWNLOAD_DELAY: 1.0`：每次请求间隔 1 秒——**礼貌爬取**，不给目标站点压力，也降低被封 IP 风险。
   - `ROBOTSTXT_OBEY: True`：遵守网站的 robots.txt 协议。
4. **`parse`（列表页回调）**：用 CSS 选择器 `a.article-link::attr(href)` 提取详情页链接，`yield response.follow(...)` 交给 `parse_detail` 处理；同时找 `a.next-page` 翻页，递归调用 `parse` 自己。
   - `yield` 是关键：Scrapy 是**异步生成器**模型，`yield` 一个请求/Item 就是"交给引擎调度"，不用手写多线程。
5. **`parse_detail`（详情页回调）**：抓标题（`h1`）、正文（`div.content p`），填进 `TcmDocItem`，空正文则丢弃（`if item["content"]`）。
   - CSS 选择器是**站点特定的**，换站点要改这里——所以叫"骨架"而非"成品爬虫"。

## data/parser/pdf_parser.py —— PDF 文本解析

```python
"""PDF 文本解析（PyPDF2），逐页抽取为章节。"""

from pathlib import Path

from PyPDF2 import PdfReader


def parse_pdf(path: str | Path) -> dict:
    """解析 PDF 文件，返回统一结构化文档。

    若某页无可提取文本（扫描件），content 为空串，
    可交由 data.parser.ocr_parser 处理对应页面图片。
    """
    path = Path(path)
    reader = PdfReader(str(path))

    sections = []
    for i, page in enumerate(reader.pages):
        text = (page.extract_text() or "").strip()
        if text:
            sections.append({"section": f"第{i + 1}页", "content": text})

    return {"source": str(path), "format": "pdf", "sections": sections}
```

**讲解**：
- `PdfReader` 读入 PDF，`page.extract_text()` 逐页抽文本。
- 每页变成一个 `section`（`{"section":"第1页","content":…}`）。
- `(page.extract_text() or "")`：扫描件 PDF 没有可提取文本时会返回 `None`，用 `or ""` 兜底成空串，避免 `.strip()` 报错。
- 注释点明了**协作关系**：PDF 是扫描件时，交给 `ocr_parser` 处理——这是两个解析器之间的"接力"。

## data/parser/ocr_parser.py —— 扫描件 OCR

```python
"""扫描件/图片 OCR 解析（Tesseract，需安装 chi_sim 语言包）。"""

from pathlib import Path

import pytesseract
from PIL import Image


def ocr_image(path: str | Path, lang: str = "chi_sim+eng") -> str:
    """对单张图片执行 OCR，返回识别文本。"""
    with Image.open(path) as img:
        # 灰度化可提升古籍扫描件识别率
        return pytesseract.image_to_string(img.convert("L"), lang=lang).strip()


def parse_image(path: str | Path) -> dict:
    """解析图片文件为统一结构化文档。"""
    path = Path(path)
    return {
        "source": str(path),
        "format": "ocr",
        "sections": [{"section": "OCR识别", "content": ocr_image(path)}],
    }
```

**讲解**：
- `pytesseract` 是 Tesseract OCR 引擎的 Python 封装。
- `lang="chi_sim+eng"`：简体中文 + 英文。这对应 Dockerfile 里装 `tesseract-ocr-chi-sim` 语言包（第 25 步会看到）。
- `img.convert("L")`：**转灰度**再识别，古籍扫描件（泛黄、墨迹）的识别率更高。
- `with Image.open(...)`：上下文管理器，用完自动释放图片资源。

## data/parser/__init__.py —— 解析分发入口（按扩展名路由）

```python
"""文档解析模块：PDF / 扫描件 OCR / 纯文本，输出统一结构化 JSON。"""

import json
from pathlib import Path

from common.config import PROJECT_ROOT

RAW_DATA_DIR = PROJECT_ROOT / "data" / "raw_data"
PARSED_DIR = RAW_DATA_DIR / "parsed"


def save_parsed(doc: dict, out_dir: Path = PARSED_DIR) -> Path:
    """将解析结果保存为结构化 JSON，返回文件路径。"""
    out_dir.mkdir(parents=True, exist_ok=True)
    out_path = out_dir / (Path(doc["source"]).stem + ".json")
    with open(out_path, "w", encoding="utf-8") as f:
        json.dump(doc, f, ensure_ascii=False, indent=2)
    return out_path


def parse_file(path: str | Path) -> dict:
    """按扩展名分发解析器，输出统一格式：
    {"source": ..., "format": ..., "sections": [{"section": ..., "content": ...}]}
    """
    path = Path(path)
    suffix = path.suffix.lower()

    if suffix == ".pdf":
        from data.parser.pdf_parser import parse_pdf
        return parse_pdf(path)
    if suffix in {".png", ".jpg", ".jpeg", ".bmp", ".tiff"}:
        from data.parser.ocr_parser import parse_image
        return parse_image(path)
    if suffix in {".txt", ".md"}:
        return {
            "source": str(path),
            "format": suffix.lstrip("."),
            "sections": [{"section": "全文",
                          "content": path.read_text(encoding="utf-8", errors="ignore")}],
        }
    raise ValueError(f"不支持的文件格式: {suffix}")
```

**逐段讲解**：

1. **`parse_file` 是"门面"（Facade）**：调用方只跟 `parse_file` 打交道，内部按后缀名分发到 pdf/ocr/txt 三种实现。**调用方不用关心底层细节**。
2. **延迟导入**：`from data.parser.pdf_parser import parse_pdf` 放在函数体内——只在真正解析 PDF 时才 import 对应模块，避免"解析 txt 也要装 PyPDF2"。
3. **`suffix.lower()`**：统一转小写，`A.PDF`、`a.pdf` 都能识别。
4. **`.txt`/`.md` 直接读文本**：`errors="ignore"` 忽略无法解码的字符（容错），`.lstrip(".")` 把 `.txt` 变成 `txt`。
5. **不支持的格式抛 `ValueError`**：显式报错优于静默失败。
6. **`save_parsed`**：把解析结果落盘成 JSON（`ensure_ascii=False` 保留中文、`indent=2` 便于人读）。文件名用 `Path(doc["source"]).stem`（取源文件名去扩展名）。
7. **`RAW_DATA_DIR`/`PARSED_DIR`**：解析结果统一放 `data/raw_data/parsed/`（该目录已 gitignore，见 `.gitignore` 里的 `data/raw_data/`）。

# 第 12 步：retrieval/vector_index/index_builder.py —— 构建 FAISS 向量索引

> 把 Neo4j 里的实体"转成向量"存进 FAISS，供语义检索使用。这是"③存储"阶段中向量侧的建库脚本。

```python
"""FAISS 向量索引构建：从 Neo4j 读取实体 → GTE 向量化 → 写入 FAISS。

运行方式: python -m retrieval.vector_index.index_builder
"""

import json
from pathlib import Path

import faiss
import numpy as np

from common.config import PROJECT_ROOT, load_config
from common.embedding import EmbeddingService
from kg.neo4j_loader import get_driver


def fetch_entities(driver, label: str) -> list[dict]:
    """读取指定标签的全部节点，拼接用于向量化的描述文本。"""
    with driver.session() as session:
        records = session.run(
            f"MATCH (n:{label}) RETURN elementId(n) AS id, n.name AS name, "
            f"coalesce(n.description, '') AS description"
        ).data()
    entities = []
    for r in records:
        text = r["name"] + ("：" + r["description"] if r["description"] else "")
        entities.append({
            "entity_id": r["id"],
            "label": label,
            "name": r["name"],
            "text": text,  # 向量化文本
        })
    return entities


def build_collection(driver, embedder, collection: dict, out_dir: Path) -> int:
    """构建单个集合的 FAISS 索引与 ID 映射文件，返回实体数。"""
    entities = fetch_entities(driver, collection["entity_label"])
    if not entities:
        return 0

    vectors = embedder.encode([e["text"] for e in entities])
    index = faiss.IndexFlatIP(vectors.shape[1])
    index.add(np.ascontiguousarray(vectors))

    faiss.write_index(index, str(out_dir / f"{collection['name']}.faiss"))
    with open(out_dir / f"{collection['name']}_map.json", "w", encoding="utf-8") as f:
        json.dump(entities, f, ensure_ascii=False, indent=2)
    return len(entities)


def main():
    cfg = load_config("faiss_config.yaml")
    out_dir = PROJECT_ROOT / cfg["index"]["dir"]
    out_dir.mkdir(parents=True, exist_ok=True)

    embedder = EmbeddingService.get_instance()
    driver = get_driver()
    try:
        for collection in cfg["collections"]:
            n = build_collection(driver, embedder, collection, out_dir)
            print(f"[{collection['name']}] 索引构建完成，实体数: {n}")
    finally:
        driver.close()


if __name__ == "__main__":
    main()
```

**逐段讲解**：

1. **`fetch_entities`**：
   - Cypher 查询某标签（如 `Herb`）的全部节点，取 `elementId(n)`（Neo4j 节点内部 ID）、`name`、`description`。
   - `coalesce(n.description, '')`：Neo4j 的 COALESCE 函数，`description` 为 null 时兜底为空串。
   - `text = name + "：" + description`：**把 name 和描述拼成一句话再向量化**，让向量同时携带"实体名"和"语义描述"。
   - 每个实体存 4 个字段，其中 `entity_id`（Neo4j 内部 ID）是**回查图库的钥匙**。
2. **`build_collection`**：
   - `embedder.encode(...)`：批量向量化（第 7 步的单例）。
   - `faiss.IndexFlatIP(vectors.shape[1])`：建内积索引，维度自动取自向量（768）。
   - `np.ascontiguousarray`：确保内存连续，FAISS 底层 C 库要求连续内存。
   - **双文件输出**：`.faiss`（向量索引）+ `_map.json`（ID 映射）。检索时 FAISS 只返回"第几个向量"（数字下标），要靠 `_map.json` 把下标翻译回实体信息——**这是 FAISS 的标准配套模式**。
3. **`main`**：读配置 → 建输出目录 → 循环构建每个集合（`configs/faiss_config.yaml` 里的 `collections` 三个集合）。`try/finally` 关连接。
4. **配置驱动再次体现**：加一个"证型"向量集合，只需在 YAML 里加一条，代码零改动。

# 第 13 步：retrieval/vector_index/retriever.py —— FAISS 向量检索器

> 检索侧的向量引擎：把用户问题转成向量，去所有集合里找"语义最接近"的实体。
> 注意它和 `index_builder.py` 是一对：**一个建索引（离线），一个查索引（在线）**。

```python
"""FAISS 向量检索器：跨集合语义检索。"""

import json

import faiss
import numpy as np

from common.config import PROJECT_ROOT, load_config
from common.embedding import EmbeddingService


class VectorRetriever:
    """加载全部 FAISS 集合索引，对查询做跨集合语义召回。"""

    def __init__(self):
        cfg = load_config("faiss_config.yaml")
        self.index_dir = PROJECT_ROOT / cfg["index"]["dir"]
        self.collections: list[dict] = []

        for collection in cfg["collections"]:
            faiss_path = self.index_dir / f"{collection['name']}.faiss"
            map_path = self.index_dir / f"{collection['name']}_map.json"
            if not (faiss_path.exists() and map_path.exists()):
                continue  # 索引未构建的集合跳过
            with open(map_path, "r", encoding="utf-8") as f:
                entity_map = json.load(f)
            self.collections.append({
                "name": collection["name"],
                "index": faiss.read_index(str(faiss_path)),
                "entity_map": entity_map,
            })

    @property
    def available(self) -> bool:
        return len(self.collections) > 0

    def search(self, query: str, top_k: int = 10) -> list[dict]:
        """返回按相似度降序的候选：{entity_id, label, name, text, score}"""
        if not self.available:
            return []

        query_vec = EmbeddingService.get_instance().encode([query])
        query_vec = np.ascontiguousarray(query_vec)

        results = []
        for collection in self.collections:
            index, entity_map = collection["index"], collection["entity_map"]
            k = min(top_k, index.ntotal)
            if k == 0:
                continue
            scores, idxs = index.search(query_vec, k)
            for score, idx in zip(scores[0], idxs[0]):
                if idx < 0:
                    continue
                entity = entity_map[idx]
                results.append({
                    "entity_id": entity["entity_id"],
                    "label": entity["label"],
                    "name": entity["name"],
                    "text": entity["text"],
                    "score": float(score),
                })

        results.sort(key=lambda x: x["score"], reverse=True)
        return results[:top_k]
```

**逐段讲解**：

1. **`__init__` 的"惰性 + 容错"加载**：
   - 遍历配置里的集合，`.faiss` 和 `_map.json` **都存在**才加载，缺一个就 `continue` 跳过——所以"索引还没建好"时程序不崩，只是该集合不参与检索。
   - `faiss.read_index` 把磁盘上的索引读回内存。
2. **`available` 属性**：告诉调用方"我到底有没有可用数据"。`fusion.py` 会用它判断是否降级。
3. **`search` 跨集合检索**：
   - 查询向量化（复用单例 embedding）。
   - `index.search(query_vec, k)`：FAISS 返回 `(scores, idxs)` 两个矩阵——每个查询向量的前 k 个相似向量的分数和下标。
   - `k = min(top_k, index.ntotal)`：防止"集合里只有 3 个实体却要 top 10"越界。
   - `idx < 0`：FAISS 用 `-1` 表示"没找到足够的邻居"，跳过。
   - 用 `idx` 从 `entity_map` 反查实体信息，**拼成统一的 dict 结构**（`entity_id/label/name/text/score`）。
4. **最后全局排序**：三个集合各自召回后，**合并、按 `score` 降序、截断到 top_k**。
   - 注意这里的 `score` 是内积相似度（已归一化，等价余弦），越大越相似。
5. **统一返回结构的意义**：三路检索（向量/图谱/关键词）都会返回这种 `{name, text, score…}` 结构，`fusion.py` 才能统一融合——**接口约定是融合的前提**。

# 第 14 步：retrieval/graph_retriever/cypher_retriever.py —— 图谱检索器

> 检索侧的图引擎：从 Neo4j 里查结构化事实。它有两种查法：
> ① **结构化检索**（实体名匹配 + 邻域扩展，纯 Cypher，快且准）；
> ② **自然语言转 Cypher**（用 DeepSeek 把用户问题翻译成 Cypher 再执行）。
> 这个文件还示范了**防注入安全校验**——很重要。

```python
"""Neo4j 图谱检索器：实体名匹配、邻域事实扩展、自然语言转 Cypher。"""

import re

from common.config import load_config
from common.llm import get_llm
from kg.neo4j_loader import get_driver

CYPHER_PROMPT = """你是 Neo4j Cypher 查询专家。根据图谱 Schema 将用户问题转换为只读 Cypher 查询。

图谱 Schema：
{schema}

要求：
1. 只允许 MATCH / RETURN / WHERE / LIMIT，禁止任何写操作
2. 节点名称用中文精确匹配或 CONTAINS 模糊匹配
3. 只输出 Cypher 语句本身，不要任何解释

用户问题：{question}
"""

# 只读 Cypher 白名单校验
_FORBIDDEN = re.compile(
    r"\b(CREATE|MERGE|DELETE|DETACH|SET|REMOVE|DROP|CALL\s+db\.|LOAD)\b", re.I
)


class GraphRetriever:
    """基于 Neo4j 的结构化图谱检索。"""

    def __init__(self, driver=None):
        self.driver = driver or get_driver()
        self.labels = [
            n["label"] for n in load_config("neo4j_config.yaml")["schema"]["nodes"]
        ]

    # ---------- 结构化检索 ----------

    def find_entities(self, query: str, limit: int = 5) -> list[dict]:
        """跨标签查找问题中提及的实体（问题文本包含实体名）。"""
        found = []
        with self.driver.session() as session:
            for label in self.labels:
                records = session.run(
                    f"MATCH (n:{label}) WHERE $q CONTAINS n.name "
                    f"RETURN n.name AS name LIMIT $limit",
                    q=query,
                    limit=limit,
                ).data()
                found.extend({"name": r["name"], "label": label} for r in records)
        return found[:limit]

    def neighborhood_facts(self, name: str, label: str, limit: int = 20) -> list[str]:
        """获取节点一跳邻域的事实描述（可读文本行）。"""
        with self.driver.session() as session:
            records = session.run(
                f"MATCH (a:{label} {{name: $name}})-[r]-(b) "
                f"RETURN type(r) AS rel, labels(b)[0] AS blabel, b.name AS bname, "
                f"startNode(r).name = $name AS outgoing LIMIT $limit",
                name=name,
                limit=limit,
            ).data()
        facts = []
        for r in records:
            if r["outgoing"]:
                facts.append(f"({name})-[:{r['rel']}]->({r['bname']})")
            else:
                facts.append(f"({r['bname']})-[:{r['rel']}]->({name})")
        return facts

    def search(self, query: str, top_k: int = 10) -> list[dict]:
        """图谱结构化检索：实体匹配 + 邻域扩展，输出文本事实候选。"""
        results = []
        for entity in self.find_entities(query, limit=top_k):
            facts = self.neighborhood_facts(entity["name"], entity["label"])
            if facts:
                results.append({
                    "name": entity["name"],
                    "label": entity["label"],
                    "text": f"{entity['name']}：" + "；".join(facts),
                    "facts": facts,
                })
        return results[:top_k]

    # ---------- 自然语言转 Cypher ----------

    def generate_cypher(self, question: str) -> str:
        """用 DeepSeek 将自然语言转换为 Cypher（含只读白名单校验）。"""
        schema = self._schema_text()
        resp = get_llm(temperature=0).invoke(
            CYPHER_PROMPT.format(schema=schema, question=question)
        )
        cypher = resp.content.strip().strip("`")
        if cypher.upper().startswith("CYPHER"):
            cypher = cypher.split("\n", 1)[-1]
        if _FORBIDDEN.search(cypher):
            raise ValueError(f"生成的 Cypher 含写操作，已拒绝执行: {cypher}")
        return cypher

    def run_cypher(self, cypher: str, limit: int = 50) -> list[dict]:
        """执行只读 Cypher 并返回记录列表。"""
        if _FORBIDDEN.search(cypher):
            raise ValueError("禁止执行非只读 Cypher")
        with self.driver.session() as session:
            return session.run(cypher + f" LIMIT {limit}").data()

    def _schema_text(self) -> str:
        cfg = load_config("neo4j_config.yaml")["schema"]
        nodes = "、".join(n["label"] for n in cfg["nodes"])
        rels = "、".join(cfg["relations"])
        return (
            f"节点标签: {nodes}（均有 name 属性）\n"
            f"关系类型: {rels}\n"
            f"示例: MATCH (f:Fangji {{name: '柴胡疏肝散'}})-[:COMPOSED_OF]->(h:Herb) RETURN h.name"
        )
```

**逐段讲解**：

1. **`_FORBIDDEN` 正则 —— 安全红线**：
   - 匹配 `CREATE/MERGE/DELETE/DETACH/SET/REMOVE/DROP/CALL db./LOAD` 等写操作关键字（`re.I` 忽略大小写）。
   - 这是**防止大模型生成恶意/误写的 Cypher 删库**的兜底。`generate_cypher` 和 `run_cypher` 双重校验（生成后查一次、执行前再查一次），纵深防御。
   - 你会在 `agents/graph_agent.py` 里看到它被实际调用。
2. **结构化检索三件套**（`find_entities` → `neighborhood_facts` → `search`）：
   - `find_entities`：`WHERE $q CONTAINS n.name`——问题文本里**包含**某个实体名就命中（比如问"柴胡疏肝散的组成"，"柴胡疏肝散"在问题里，能匹配到）。跨所有标签查。
   - `neighborhood_facts`：`MATCH (a)-[r]-(b)` 取一跳邻居，`startNode(r).name = $name` 判断方向，格式化成 `(A)-[:关系]->(B)` 的可读文本。
   - `search`：把命中的每个实体 + 其邻居事实打包成 `{name, label, text, facts}`。
3. **自然语言转 Cypher**（`generate_cypher`）：
   - 用 `get_llm(temperature=0)`（要稳定）把问题翻译成 Cypher，Prompt 里注入 `_schema_text()` 的 Schema 摘要。
   - `resp.content.strip().strip("`")`：去掉 LLM 常带的 markdown 代码块反引号。
   - `if cypher.upper().startswith("CYPHER")`：有些 LLM 会输出 `Cypher: MATCH...`，把前缀去掉。
   - 最后过 `_FORBIDDEN` 白名单，含写操作直接抛异常（**拒绝执行**）。
4. **`run_cypher`**：执行前再校验一次，并强制追加 `LIMIT` 防止超大结果集拖垮内存。
5. **`_schema_text`**：把 `neo4j_config.yaml` 的 Schema 转成一段文字喂给 LLM，让 LLM"知道"有哪些标签和关系可用——**Prompt 与配置同步**（和第 4 步 `{entity_types}` 同样的思想）。

# 第 15 步：retrieval/hybrid_retriever/keyword_retriever.py —— BM25 关键词检索

> 第三路检索：BM25 关键词匹配。它不靠语义向量，而是靠"词频"——用户问"柴胡"，就把含"柴胡"的实体找出来。
> 与向量检索（语义近但可能不精确）形成互补：**向量管"意思像"，关键词管"字面像"**。

```python
"""BM25 关键词检索器：面向中医药术语的精确召回。"""

import json

from rank_bm25 import BM25Okapi

from common.config import PROJECT_ROOT, load_config


def _tokenize(text: str) -> list[str]:
    """中文二元分词 + 连续英文/数字整词，兼顾术语与拉丁名。"""
    tokens, buf = [], ""
    for ch in text:
        if ch.isalnum():
            buf += ch
        else:
            if buf:
                tokens.append(buf.lower())
                buf = ""
    if buf:
        tokens.append(buf.lower())
    # 中文部分做字二元组
    cn = "".join(ch for ch in text if "\u4e00" <= ch <= "\u9fff")
    tokens += [cn[i:i + 2] for i in range(len(cn) - 1)]
    return tokens


class KeywordRetriever:
    """基于 FAISS 集合实体映射构建 BM25 语料库。"""

    def __init__(self):
        cfg = load_config("faiss_config.yaml")
        index_dir = PROJECT_ROOT / cfg["index"]["dir"]

        self.corpus: list[dict] = []
        for collection in cfg["collections"]:
            map_path = index_dir / f"{collection['name']}_map.json"
            if not map_path.exists():
                continue
            with open(map_path, "r", encoding="utf-8") as f:
                self.corpus.extend(json.load(f))

        tokenized = [_tokenize(e["text"]) for e in self.corpus]
        self.bm25 = BM25Okapi(tokenized) if tokenized else None

    @property
    def available(self) -> bool:
        return self.bm25 is not None

    def search(self, query: str, top_k: int = 10) -> list[dict]:
        if not self.available:
            return []
        scores = self.bm25.get_scores(_tokenize(query))
        ranked = sorted(range(len(scores)), key=lambda i: scores[i], reverse=True)
        results = []
        for i in ranked[:top_k]:
            if scores[i] <= 0:
                break
            e = self.corpus[i]
            results.append({
                "entity_id": e["entity_id"],
                "label": e["label"],
                "name": e["name"],
                "text": e["text"],
                "score": float(scores[i]),
            })
        return results
```

**逐段讲解**：

1. **`_tokenize` —— 中文分词的自制方案**：
   - 英文/数字：连续字符算一个词（`ch.isalnum()` 判断），如 "Vitamin"、"768"。
   - 中文：**字二元组**（bigram）——把"柴胡疏肝散"切成"柴胡""胡疏""疏肝""肝散"。因为中文没有空格分词，而项目没引入 jieba 等分词库，用二元组是轻量又有效的折中（中医术语多为 2 字词，如"柴胡""疏肝"）。
   - `"\u4e00" <= ch <= "\u9fff"` 是判断"是不是汉字"的 Unicode 区间。
2. **语料复用**：BM25 的语料直接读 `_map.json`（第 12 步生成的实体映射）——**和向量检索共用同一份实体数据**，不另建语料库。
3. **`BM25Okapi`**：rank-bm25 库的 BM25 实现。`get_scores` 返回每个文档的匹配分数。
4. **`scores[i] <= 0: break`**：分数 <= 0 表示"毫无关键词命中"，直接停（因为 `ranked` 已降序，后面只会更低）。**只返回真正命中的**，避免用 0 分文档充数。
5. **返回结构依然对齐**：`{entity_id, label, name, text, score}`，和第 13/14 步一致，供融合使用。

# 第 16 步：retrieval/hybrid_retriever/fusion.py —— 三路融合 + 精排

> 检索系统的"总装车间"：把图谱、向量、关键词三路召回结果**融合排序（RRF）**，再用 COROM 模型**精排**。
> 这是整个 RAG 的检索核心，也是"双引擎混合检索"的真正实现。

```python
"""双引擎混合检索：图谱 + 向量 + BM25 三路召回，RRF 融合，COROM 精排。"""

from common.config import load_config
from retrieval.graph_retriever.cypher_retriever import GraphRetriever
from retrieval.hybrid_retriever.keyword_retriever import KeywordRetriever
from retrieval.vector_index.retriever import VectorRetriever


def rrf_fusion(ranked_lists: list[list[dict]], weights: list[float],
               rrf_k: int = 60) -> list[dict]:
    """RRF（Reciprocal Rank Fusion）加权融合多路排序结果。"""
    fused: dict[str, dict] = {}
    for results, weight in zip(ranked_lists, weights):
        for rank, item in enumerate(results):
            key = item.get("name") or item.get("text", "")[:50]
            entry = fused.setdefault(key, {**item, "rrf_score": 0.0, "sources": []})
            entry["rrf_score"] += weight / (rrf_k + rank + 1)
            entry["sources"].append(item.get("source", "unknown"))
    return sorted(fused.values(), key=lambda x: x["rrf_score"], reverse=True)


class HybridRetriever:
    """三路混合检索入口，各路独立容错（某一路不可用不影响整体）。"""

    def __init__(self):
        cfg = load_config("agent_config.yaml")
        self.retrieval_cfg = cfg["retrieval"]
        self.rerank_cfg = cfg.get("rerank", {})

        self.vector = VectorRetriever()
        self.keyword = KeywordRetriever()
        try:
            self.graph = GraphRetriever()
        except Exception:
            self.graph = None  # Neo4j 未启动时降级为双路检索
        self._reranker = None

    def search(self, query: str, top_k: int | None = None) -> list[dict]:
        """执行混合检索，返回精排后的 Top-K 上下文候选。"""
        top_k = top_k or self.retrieval_cfg["top_k"]
        candidate_k = top_k * self.retrieval_cfg.get("candidate_multiplier", 2)
        weights_cfg = self.retrieval_cfg["weights"]

        # 三路并行召回（此处顺序执行，各路独立容错）
        graph_results = self._safe_search(
            self.graph, query, candidate_k, "graph")
        vector_results = self._safe_search(
            self.vector, query, candidate_k, "vector")
        keyword_results = self._safe_search(
            self.keyword, query, candidate_k, "keyword")

        fused = rrf_fusion(
            [graph_results, vector_results, keyword_results],
            [weights_cfg["graph"], weights_cfg["vector"], weights_cfg["keyword"]],
            rrf_k=self.retrieval_cfg.get("rrf_k", 60),
        )

        if self.rerank_cfg.get("enabled"):
            fused = self._rerank(query, fused, top_k * 2)
        return fused[:top_k]

    def build_context(self, results: list[dict]) -> str:
        """将检索结果拼接为供 LLM 使用的参考上下文。"""
        lines = []
        for i, item in enumerate(results, 1):
            lines.append(f"[{i}] {item.get('text') or item.get('name', '')}")
        return "\n".join(lines)

    # ---------- 内部方法 ----------

    @staticmethod
    def _safe_search(retriever, query: str, k: int, source: str) -> list[dict]:
        if retriever is None or getattr(retriever, "available", True) is False:
            return []
        try:
            results = retriever.search(query, top_k=k)
            for r in results:
                r["source"] = source
            return results
        except Exception:
            return []

    def _rerank(self, query: str, candidates: list[dict], limit: int) -> list[dict]:
        """达摩院 COROM 精排（ModelScope 下载），失败时降级为 RRF 顺序。"""
        texts = [c.get("text") or c.get("name", "") for c in candidates]
        if not texts:
            return candidates
        try:
            if self._reranker is None:
                from modelscope.pipelines import pipeline
                from modelscope.utils.constant import Tasks
                self._reranker = pipeline(
                    Tasks.text_ranking, model=self.rerank_cfg["model"])
            input_data = {"source_sentence": [query], "sentences_to_compare": texts}
            result = self._reranker(input_data)
            order = result.get("index", list(range(len(candidates))))
            scores = result.get("scores")
            reranked = [candidates[i] for i in order if i < len(candidates)]
            if scores:
                for item, score in zip(reranked, scores):
                    item["rerank_score"] = float(score)
            return reranked[:limit]
        except Exception:
            return candidates[:limit]
```

**逐段讲解**：

1. **`rrf_fusion` —— RRF 融合算法（核心）**：
   - RRF = Reciprocal Rank Fusion（倒数排名融合）。公式：`score = Σ weight / (k + rank + 1)`，`k` 是常数 60，`rank` 是某条结果在某一路上的排名（从 0 开始）。
   - 直觉：**一个文档在越多路里排名越靠前，总分越高**。第 1 名得 `1/61`，第 2 名 `1/62`……递减，鼓励"各路共识"的文档。
   - `key = item.get("name") or item.get("text","")[:50]`：用名字当去重键，同一实体在多路出现时合并成一条，并把 `source` 记录到 `sources` 列表（溯源用）。
   - `{**item, ...}`：字典展开，复制原条目再追加 `rrf_score`/`sources` 字段。
2. **`HybridRetriever.__init__` 的容错设计**：
   - `try: self.graph = GraphRetriever() except: self.graph = None`——**Neo4j 没启动时，图谱路降级为 None**，系统退化成"向量 + 关键词"双路，不整体崩掉。这是"优雅降级"（graceful degradation）。
3. **`search` 全流程**：
   - `candidate_k = top_k * 2`：每路先召回 2 倍候选（"广撒网"），融合精排后再截回 top_k（"精选"）。
   - 三路召回都走 `_safe_search`（**独立容错**：某一路抛异常只影响它自己，返回空列表）。
   - 融合 → 若 `rerank.enabled` 则 COROM 精排（先取 `top_k*2` 再精排）→ 最终 `fused[:top_k]`。
4. **`_safe_search`**：
   - 先判 `available`（索引/语料没建好就跳过），再 `try/except` 包住真实搜索，异常返回 `[]`。
   - 给每条结果打上 `source` 标签（`graph/vector/keyword`），供溯源显示"这条结果来自哪一路"。
   - `@staticmethod`：不依赖实例状态，纯粹的工具函数。
5. **`_rerank` —— COROM 精排 + 降级**：
   - **懒加载**：`self._reranker is None` 时才初始化 COROM 管道（模型很重，用到再加载）。
   - `result.get("index")`：COROM 返回重排后的下标顺序，据此重排候选。
   - 整个包在 `try/except` 里：**COROM 加载/推理失败就退回 RRF 的原始顺序**（`return candidates[:limit]`），绝不影响主流程。
6. **`build_context`**：把检索结果拼成 `[1] …\n[2] …` 的参考文本，喂给问答/生成 Agent。编号 `[1][3]` 就是问答答案里"引用资料编号"的来源（见第 18 步）。

> 🎯 **第二阶段小结**（第 10~16 步）：检索系统 = **三路召回（图/向量/关键词）+ RRF 融合 + COROM 精排**。
> 每一路都独立容错、返回统一结构；融合层把三路"共识"推到前面；精排层再微调。
> 下面进入**多智能体层**——它们站在检索系统之上，回答"用户到底要什么"。

# 第 17 步：agents/intent_agent.py —— 意图识别 Agent

> 多智能体系统的"前台接待"：判断用户这句话**到底想干嘛**，然后把任务分发给对应的业务 Agent。
> 四种意图：问答 / 图谱查询 / 内容生成 / 发布。

```python
"""意图识别 Agent：将用户输入路由到对应业务 Agent。"""

from typing import Literal

from pydantic import BaseModel, Field

from common.llm import get_llm

IntentType = Literal["qa", "graph_query", "content_generation", "publish"]

INTENT_PROMPT = """你是意图识别专家。判断用户输入属于以下哪种意图：
- qa：中医药知识问答（如"柴胡有什么功效"、"胸闷胁痛用什么方子"）
- graph_query：查询知识图谱结构化数据（如"列出柴胡疏肝散的组成"、"图谱里有哪些方剂"）
- content_generation：生成科普图文内容（如"帮我写一篇关于艾灸的小红书笔记"）
- publish：发布内容到平台（如"发布这篇笔记"）
只输出意图标签，不要解释。"""


class IntentResult(BaseModel):
    intent: IntentType = Field(description="用户意图类别")


def identify_intent(state: dict) -> dict:
    """LangGraph 节点：解析最后一条用户消息的意图。"""
    messages = state.get("messages", [])
    question = messages[-1].content if messages else ""

    chain = get_llm(temperature=0).with_structured_output(IntentResult)
    try:
        result = chain.invoke([
            ("system", INTENT_PROMPT),
            ("human", question),
        ])
        intent = result.intent
    except Exception:
        intent = "qa"  # 识别失败时默认走问答

    return {"intent": intent}
```

**逐段讲解**：

1. **`Literal["qa", "graph_query", "content_generation", "publish"]`**：
   - `Literal` 是 Python 类型提示，限定值只能是这 4 个之一。
   - 配合 Pydantic + `with_structured_output`，**强制 LLM 只能返回这 4 个标签**，不会输出乱七八糟的意图。
2. **`identify_intent(state)` 是"LangGraph 节点"**：
   - LangGraph 把每个处理步骤叫做"节点（node）"，节点是**一个函数，输入 `state`（状态字典），返回要更新的字段**。
   - 这里从 `state["messages"]` 取最后一条用户消息，识别意图，返回 `{"intent": intent}` 更新状态。
3. **`messages[-1]`**：取"最后一条消息"——因为 LangGraph 的 `messages` 是累积的消息列表，用户最新的话在最后。
4. **容错**：LLM 调用失败时 `intent = "qa"` 兜底——**默认走问答，保证系统总有输出**。
5. 这个节点不产生最终答案，只**"贴标签"**，真正的路由在 `workflow.py`（第 22 步）根据这个标签决定。

# 第 18 步：agents/qa_agent.py —— 问答 Agent（RAG 流水线）

> 核心业务 Agent：**混合检索 → 拼上下文 → DeepSeek 生成答案**，并带"溯源"。
> 它把第 16 步的 `HybridRetriever` 真正用起来，是 RAG（检索增强生成）的完整闭环。

```python
"""问答 Agent：RAG 流水线（混合检索 → 上下文构建 → DeepSeek 生成）。"""

from common.llm import get_llm
from retrieval.hybrid_retriever import HybridRetriever

QA_PROMPT = """你是严谨的中医药领域专家助手。请仅依据下方【参考资料】回答用户问题。

要求：
1. 回答必须有据可依，禁止编造资料中不存在的药材、方剂或功效
2. 若参考资料不足以回答，明确告知用户"知识库中暂无相关记载"
3. 在回答末尾标注引用的资料编号，如 [1][3]
4. 涉及用药的内容需提醒"请遵医嘱"

【参考资料】
{context}

【用户问题】
{question}"""

_hybrid: HybridRetriever | None = None


def _get_hybrid() -> HybridRetriever:
    global _hybrid
    if _hybrid is None:
        _hybrid = HybridRetriever()
    return _hybrid


def qa_handler(state: dict) -> dict:
    """LangGraph 节点：执行 RAG 问答，返回答案与溯源信息。"""
    question = state["messages"][-1].content
    hybrid = _get_hybrid()

    results = hybrid.search(question)
    context = hybrid.build_context(results)

    answer = get_llm().invoke(
        QA_PROMPT.format(context=context or "（无相关资料）", question=question)
    ).content

    sources = [
        {"name": r.get("name", ""), "label": r.get("label", ""),
         "text": r.get("text", ""), "retrieved_by": r.get("sources", [])}
        for r in results
    ]
    return {"answer": answer, "sources": sources}


def qa_stream(question: str):
    """流式问答生成器（供前端打字机效果使用），先 yield 溯源再 yield 文本块。"""
    hybrid = _get_hybrid()
    results = hybrid.search(question)
    context = hybrid.build_context(results)

    yield {"type": "sources", "data": results}

    stream = get_llm().stream(
        QA_PROMPT.format(context=context or "（无相关资料）", question=question)
    )
    for chunk in stream:
        if chunk.content:
            yield {"type": "text", "data": chunk.content}
```

**逐段讲解**：

1. **`QA_PROMPT` —— 防幻觉的 Prompt 设计**：
   - "仅依据【参考资料】回答"、"禁止编造"、"不足则明确告知暂无记载"——这是**RAG 防幻觉的核心**：把大模型"锁"在检索到的资料里，不让它自由发挥。
   - "标注引用编号 [1][3]"：对应 `build_context` 里生成的 `[1] [2] [3]` 编号，实现**可溯源**。
   - "请遵医嘱"：医疗安全的免责提醒。
2. **模块级 `_hybrid` + `_get_hybrid()`**：又一个**懒加载单例**（和第 7 步、第 16 步 COROM 同样的思想）。`HybridRetriever` 初始化会加载 FAISS 索引、连 Neo4j，很重，所以只建一次。
3. **`qa_handler`（LangGraph 节点）**：
   - `hybrid.search(question)` 检索 → `build_context` 拼上下文 → `get_llm().invoke(...)` 生成答案。
   - 返回 `{"answer": …, "sources": …}`，`sources` 是精简过的溯源信息（含 `retrieved_by` 记录来源路）。
4. **`qa_stream` —— 流式生成（generator）**：
   - `yield` 关键词让它变成**生成器**：先 yield 溯源数据，再逐块 yield LLM 的文本。
   - `get_llm().stream()` 是流式接口（token 一个一个往外吐），前端用这个实现"打字机效果"。
   - `if chunk.content`：跳过空块。
   - **两个入口并存**：`qa_handler` 给 LangGraph 工作流用（一次性返回），`qa_stream` 给 Streamlit 页面用（打字机）。功能相同，接口不同。

# 第 19 步：agents/graph_agent.py —— 图谱查询 Agent

> 处理"图谱查询"意图：把用户问题翻译成 Cypher，执行只读查询，返回结构化数据。
> 它是对第 14 步 `GraphRetriever` 的封装，做一层 LangGraph 节点适配。

```python
"""图谱查询 Agent：自然语言转 Cypher，执行只读查询返回结构化数据。"""

from retrieval.graph_retriever import GraphRetriever

_retriever: GraphRetriever | None = None


def _get_retriever() -> GraphRetriever:
    global _retriever
    if _retriever is None:
        _retriever = GraphRetriever()
    return _retriever


def graph_query_handler(state: dict) -> dict:
    """LangGraph 节点：生成并执行 Cypher，返回查询结果。"""
    question = state["messages"][-1].content
    retriever = _get_retriever()

    try:
        cypher = retriever.generate_cypher(question)
        records = retriever.run_cypher(cypher)
        answer = _format_records(question, records)
        return {"answer": answer, "cypher": cypher, "graph_data": records}
    except Exception as e:
        return {"answer": f"图谱查询失败：{e}", "cypher": "", "graph_data": []}


def _format_records(question: str, records: list[dict]) -> str:
    if not records:
        return "图谱中未查询到相关数据。"
    lines = [f"针对「{question}」的图谱查询结果（共 {len(records)} 条）："]
    for i, record in enumerate(records, 1):
        fields = "，".join(f"{k}: {v}" for k, v in record.items())
        lines.append(f"{i}. {fields}")
    return "\n".join(lines)
```

**逐段讲解**：

1. **`_get_retriever()`**：又是**懒加载单例**（GraphRetriever 要连 Neo4j，只建一次）。到这里你已经第 4 次见到这个模式了（embedding / hybrid / graph / 这里的 retriever）——**凡是"初始化重"的对象，都用这个套路**。
2. **`graph_query_handler`**：
   - `generate_cypher`（LLM 翻译）→ `run_cypher`（执行）→ `_format_records`（格式化给人看）。
   - `try/except` 兜底：查询失败时返回友好提示，不把异常抛给用户。
   - 返回 3 个字段：`answer`（给用户看）、`cypher`（生成的查询语句，调试/展示用）、`graph_data`（结构化原始数据，供前端画图等复用）。
3. **`_format_records`**：
   - 无结果时返回"未查询到"，而不是空字符串。
   - 把每条记录（dict）格式化成 `1. 字段: 值，字段: 值` 的可读文本。

# 第 20 步：agents/content_agent.py —— 内容生成 Agent

> 处理"内容生成"意图：基于知识图谱检索结果，用 DeepSeek 写**小红书风格科普笔记**，还能用 Pillow 生成配图。
> 这是"内容生成"功能的完整实现，也是全项目"温度最高"的 LLM 调用（`temperature=0.7`）。

```python
"""内容生成 Agent：小红书风格图文创作（DeepSeek + 知识图谱溯源 + Pillow 配图）。"""

from pathlib import Path

from common.config import PROJECT_ROOT
from common.llm import get_llm
from retrieval.hybrid_retriever import HybridRetriever

CONTENT_PROMPT = """你是中医药科普内容创作专家，擅长小红书平台风格。请基于【参考资料】创作一篇笔记。

风格要求：
1. 标题吸引人，适当使用 Emoji（✨🌿💡 等）
2. 正文口语化、分段清晰、要点用 emoji 列表呈现
3. 结尾添加 3-5 个热门话题标签（如 #中医药养生 #健康生活）
4. 全文不超过 {max_length} 字
5. 内容必须忠于参考资料，禁止编造功效，文末注明"养生内容仅供参考，具体请遵医嘱"

输出格式：
【标题】
（标题内容）
【正文】
（正文内容）

【参考资料】
{context}

【创作主题】
{topic}"""

_hybrid: HybridRetriever | None = None


def content_generator(state: dict) -> dict:
    """LangGraph 节点：生成小红书风格图文内容。"""
    topic = state["messages"][-1].content

    global _hybrid
    if _hybrid is None:
        _hybrid = HybridRetriever()
    results = _hybrid.search(topic, top_k=5)
    context = _hybrid.build_context(results)

    from common.config import load_config
    max_length = load_config("agent_config.yaml")["content"]["max_length"]

    content = get_llm(temperature=0.7).invoke(
        CONTENT_PROMPT.format(context=context or "（无相关资料，请仅做常识性提醒）",
                              topic=topic, max_length=max_length)
    ).content

    return {"answer": content, "generated_content": content, "topic": topic}


def generate_card(title: str, body: str, out_name: str = "note_card.png") -> Path:
    """用 Pillow 生成文字配图（知识卡片）。"""
    from PIL import Image, ImageDraw, ImageFont

    width, height = 1080, 1440
    img = Image.new("RGB", (width, height), "#f7f3ea")
    draw = ImageDraw.Draw(img)

    def load_font(size: int):
        for font_path in ("msyh.ttc", "simhei.ttf", "simsun.ttc"):
            try:
                return ImageFont.truetype(font_path, size)
            except OSError:
                continue
        return ImageFont.load_default()

    title_font, body_font = load_font(56), load_font(32)

    draw.text((60, 80), title[:20], font=title_font, fill="#3d2b1f")
    y = 220
    for line in _wrap(body, 28):
        if y > height - 120:
            break
        draw.text((60, y), line, font=body_font, fill="#4a3f35")
        y += 52

    out_dir = PROJECT_ROOT / "web" / "assets"
    out_dir.mkdir(parents=True, exist_ok=True)
    out_path = out_dir / out_name
    img.save(out_path)
    return out_path


def _wrap(text: str, width: int) -> list[str]:
    lines, buf = [], ""
    for ch in text.replace("\n", "\u3000"):
        buf += ch
        if ch == "\u3000" or len(buf) >= width:
            lines.append(buf)
            buf = ""
    if buf:
        lines.append(buf)
    return lines
```

**逐段讲解**：

1. **`CONTENT_PROMPT` 的"风格注入"**：
   - 明确要求 Emoji、口语化、话题标签、字数上限 `{max_length}`（从配置读，默认 800）。
   - 仍然要求"忠于参考资料、禁止编造、遵医嘱"——**内容生成同样守 RAG 防幻觉的红线**，只是语言风格不同。
   - 用【标题】【正文】的固定格式输出，方便后续解析和发布（`publish_agent` 会取首行当标题）。
2. **`content_generator`**：
   - `_hybrid.search(topic, top_k=5)`：检索相关背景知识（只取 5 条，够了）。
   - `get_llm(temperature=0.7)`：**温度调高**让文案更生动有创意（对比问答的 0、抽取的 0）。
   - 返回 `generated_content` 字段——这是**给发布 Agent 的"接力棒"**（第 21 步会读它）。
3. **`generate_card` —— Pillow 画图**：
   - 1080×1440（3:4，适配小红书封面），米色背景 `#f7f3ea`。
   - `load_font`：**字体容错链**——依次尝试微软雅黑/黑体/宋体（Windows 常见字体），都找不到就用 PIL 默认字体。这是 Windows 环境中文渲染的常见坑点。
   - `title[:20]`：标题截断到 20 字防溢出。
   - `_wrap(body, 28)`：按 28 字一行**手动换行**（中文按字符宽度），并处理 `\n`→全角空格、超页截断（`y > height - 120`）。
4. **输出路径**：配图存到 `web/assets/note_card.png`（对应文件清单里的那张生成图）。

# 第 21 步：agents/publish_agent.py —— 发布 Agent

> 处理"发布"意图：把生成好的内容发布到小红书。
> 实际项目里它采用**半自动方案**（前端复制粘贴），这个文件里留的是**自动化接口的骨架 + 占位**。

```python
"""发布 Agent：对接小红书开放接口，一键发布图文内容。"""

import os


class PublishResult:
    def __init__(self, success: bool, message: str, url: str = ""):
        self.success = success
        self.message = message
        self.url = url

    def to_dict(self) -> dict:
        return {"success": self.success, "message": self.message, "url": self.url}


class XiaohongshuPublisher:
    """小红书发布器：通过开放平台接口发布笔记。

    凭证从环境变量 XHS_COOKIE 读取，禁止硬编码。
    实际接入时需按小红书开放平台文档补充签名与接口地址。
    """

    API_BASE = "https://edith.xiaohongshu.com/api/sns/v1"

    def __init__(self):
        self.cookie = os.getenv("XHS_COOKIE", "")

    @property
    def configured(self) -> bool:
        return bool(self.cookie)

    def publish(self, title: str, content: str,
                image_paths: list[str] | None = None) -> PublishResult:
        if not self.configured:
            return PublishResult(
                success=False,
                message="未配置小红书凭证（请在 .env 中设置 XHS_COOKIE），内容已保存为草稿。",
            )
        try:
            return self._do_publish(title, content, image_paths or [])
        except Exception as e:
            return PublishResult(success=False, message=f"发布失败：{e}")

    def _do_publish(self, title: str, content: str,
                    image_paths: list[str]) -> PublishResult:
        """实际发布逻辑占位：对接平台接口上传素材并创建笔记。"""
        # TODO: 接入小红书开放平台实际接口（素材上传 + 笔记创建）
        raise NotImplementedError("小红书开放接口尚未接入，请配置后实现 _do_publish")


def publish_handler(state: dict) -> dict:
    """LangGraph 节点：发布上一环节生成的内容。"""
    content = state.get("generated_content") or (
        state["messages"][-1].content if state.get("messages") else "")
    if not content:
        return {"answer": "没有可发布的内容，请先生成图文笔记。"}

    # 标题取内容首行或【标题】后的文本
    title = content.split("\n", 1)[0].replace("【标题】", "").strip()[:20]

    result = XiaohongshuPublisher().publish(title, content)
    return {"answer": result.message, "publish_result": result.to_dict()}
```

**逐段讲解**：

1. **`PublishResult` —— 结果对象**：封装 `success/message/url` 三个字段，`to_dict()` 方便序列化（给前端/状态用）。
2. **`XiaohongshuPublisher`**：
   - `API_BASE` 是小红书开放接口地址（预留），`cookie` 从环境变量 `XHS_COOKIE` 读——**凭证绝不硬编码**。
   - `configured` 属性判断"有没有配好凭证"。
   - `publish`：未配置 → 返回"已存草稿"的友好提示；配置了 → 调 `_do_publish`；任何异常 → 转成 `PublishResult(False)`。
   - **`_do_publish` 是 `NotImplementedError` 占位**——说明自动化发布"接口未接入"，这是有意的未完成项（README 里明说发布默认走半自动）。骨架留好，接入时只改这一个方法。
3. **`publish_handler`（LangGraph 节点）**：
   - `state.get("generated_content")`：优先取上一环节（content_agent）生成的内容——**多 Agent 之间通过 state 传递产物**。
   - 兜底：没有 `generated_content` 时取用户最后一条消息当内容。
   - 标题 = 内容首行去掉【标题】标记，截 20 字。
   - 返回 `publish_result` 结构化结果。

# 第 22 步：agents/workflow.py —— LangGraph 多智能体编排（总指挥）

> 把前面 5 个 Agent"串成一张流程图"，用 LangGraph 实现**意图识别 → 条件路由 → 业务 Agent**。
> 这是全项目的"大脑指挥层"，理解了它，5 个 Agent 如何协作就一目了然。

```python
"""LangGraph 多智能体工作流编排：意图识别 → 条件路由 → 业务 Agent。"""

from langgraph.graph import END, MessagesState, StateGraph
from langchain_core.messages import HumanMessage

from agents.content_agent import content_generator
from agents.graph_agent import graph_query_handler
from agents.intent_agent import identify_intent
from agents.publish_agent import publish_handler
from agents.qa_agent import qa_handler


class AgentState(MessagesState):
    """多 Agent 共享状态：消息流 + 意图 + 各 Agent 产出。"""

    intent: str
    answer: str
    sources: list
    cypher: str
    graph_data: list
    generated_content: str
    topic: str
    publish_result: dict


def _route_by_intent(state: AgentState) -> str:
    """条件路由：依据意图分发到对应业务 Agent。"""
    intent = state.get("intent", "qa")
    return {
        "qa": "qa_agent",
        "graph_query": "graph_agent",
        "content_generation": "content_agent",
        "publish": "publish_agent",
    }.get(intent, "qa_agent")


def build_agent_graph():
    """构建并编译多智能体协同图。"""
    workflow = StateGraph(AgentState)

    workflow.add_node("intent_agent", identify_intent)
    workflow.add_node("qa_agent", qa_handler)
    workflow.add_node("graph_agent", graph_query_handler)
    workflow.add_node("content_agent", content_generator)
    workflow.add_node("publish_agent", publish_handler)

    workflow.set_entry_point("intent_agent")
    workflow.add_conditional_edges("intent_agent", _route_by_intent, {
        "qa_agent": "qa_agent",
        "graph_agent": "graph_agent",
        "content_agent": "content_agent",
        "publish_agent": "publish_agent",
    })
    for node in ("qa_agent", "graph_agent", "content_agent", "publish_agent"):
        workflow.add_edge(node, END)

    return workflow.compile()


_app = None


def run_agent(question: str) -> dict:
    """运行一次完整 Agent 流程，返回最终状态。"""
    global _app
    if _app is None:
        _app = build_agent_graph()
    return _app.invoke({"messages": [HumanMessage(content=question)]})
```

**逐段讲解**：

1. **`AgentState(MessagesState)` —— 共享状态**：
   - `MessagesState` 是 LangGraph 内置的状态基类，自带 `messages` 字段（消息列表）。
   - 继承后**追加**了 `intent`、`answer`、`sources`、`cypher`、`graph_data`、`generated_content`、`topic`、`publish_result` 这些字段。
   - 关键机制：**所有节点共享这一个 state 字典**。`intent_agent` 写入 `intent`，`content_agent` 写入 `generated_content`，`publish_agent` 读 `generated_content`——数据通过 state 在 Agent 之间传递（对应第 21 步看到的 `state.get("generated_content")`）。
2. **`build_agent_graph()` —— 画流程图**：
   - `StateGraph` 建图 → `add_node` 注册 5 个节点（把之前的函数"挂"上去）→ `set_entry_point` 设起点。
   - `add_conditional_edges("intent_agent", _route_by_intent, {...})`：**条件路由**——从 `intent_agent` 出发，根据 `_route_by_intent` 的返回值跳到对应节点。
   - `add_edge(node, END)`：4 个业务节点处理完都指向 `END`（结束）。
   - `compile()` 把图编译成可执行对象。
3. **`_route_by_intent` —— 路由函数**：
   - 读 `state["intent"]`，用字典映射到节点名，`.get(intent, "qa_agent")` 兜底默认问答。
   - 这就是"意图识别 → 分发"的**接线处**。
4. **`run_agent` —— 对外入口**：
   - 模块级 `_app` 缓存编译好的图（**编译一次、反复用**，避免每次调用都重新 compile）。
   - `_app.invoke({"messages": [HumanMessage(...)]})`：塞一条用户消息，跑完整流程，返回最终 state。

> 用图来理解这条流程：

```text
                     ┌──────────────┐
   用户问题 ────────▶ │ intent_agent │（识别意图）
                     └──────┬───────┘
              ┌─────────────┼─────────────┬──────────────┐
        intent=qa    intent=graph   intent=content   intent=publish
              ▼             ▼              ▼               ▼
        ┌──────────┐ ┌────────────┐ ┌──────────────┐ ┌───────────────┐
        │ qa_agent │ │graph_agent │ │content_agent │ │ publish_agent │
        └────┬─────┘ └─────┬──────┘ └──────┬───────┘ └───────┬───────┘
             └─────────────┴───────────────┴─────────────────┘
                                    ▼
                                   END
```

> 🎯 **第三阶段小结**（第 17~22 步）：5 个 Agent 各有专长，`workflow.py` 用 LangGraph 把它们编排成一个"先识别意图、再分流处理"的状态机。
> 至此，**后端全部讲完**。下面进入前端（Streamlit）和部署。

## web/pages/qa.py —— 智能问答页

```python
"""智能问答页面：RAG 问答 + 打字机流式输出 + 知识溯源。"""

import streamlit as st

from agents.qa_agent import qa_stream

st.header("💬 中医药智能问答")
st.caption("基于知识图谱 + 向量双引擎混合检索，回答可溯源、拒绝幻觉")

if "chat_history" not in st.session_state:
    st.session_state.chat_history = []

for item in st.session_state.chat_history:
    with st.chat_message(item["role"]):
        st.markdown(item["content"])
        if item.get("sources"):
            with st.expander(f"📚 知识溯源（{len(item['sources'])} 条依据）"):
                for i, s in enumerate(item["sources"], 1):
                    st.markdown(
                        f"**[{i}] {s.get('name', '')}**（{s.get('label', '')}）"
                        f"\n{s.get('text', '')}"
                    )

question = st.chat_input("请输入中医药相关问题，如：柴胡疏肝散由哪些药材组成？")

if question:
    st.session_state.chat_history.append({"role": "user", "content": question})
    with st.chat_message("user"):
        st.markdown(question)

    with st.chat_message("assistant"):
        sources = []

        def _text_stream():
            global sources
            for event in qa_stream(question):
                if event["type"] == "sources":
                    sources = event["data"]
                else:
                    yield event["data"]

        # 打字机效果：逐块流式渲染回答
        answer = st.write_stream(_text_stream())

        if sources:
            with st.expander(f"📚 知识溯源（{len(sources)} 条依据）"):
                for i, s in enumerate(sources, 1):
                    st.markdown(
                        f"**[{i}] {s.get('name', '')}**（{s.get('label', '')}）"
                        f"\n{s.get('text', '')}"
                    )

    st.session_state.chat_history.append(
        {"role": "assistant", "content": answer, "sources": sources}
    )
```

**逐段讲解**：

1. **`st.session_state` —— Streamlit 的会话状态**：
   - Streamlit 每次交互都**重跑整个脚本**，普通变量会丢失。要跨交互记住数据（比如聊天历史），必须存进 `st.session_state`。
   - `if "chat_history" not in st.session_state`：首次运行时初始化。
2. **聊天界面**：
   - 先渲染历史对话（`st.chat_message` 区分用户/助手气泡），历史里带 `sources` 的展开"知识溯源"折叠面板（`st.expander`）。
   - `st.chat_input`：输入框，用户回车触发。
3. **流式输出（打字机）**：
   - `qa_stream(question)` 是第 18 步的生成器：先 yield `sources`，再逐块 yield 文本。
   - `_text_stream` 内部把 `sources` 事件收集到变量，把 `text` 事件 yield 出去。
   - `st.write_stream(...)`：Streamlit 的流式渲染 API，配合生成器实现"一个字一个字往外蹦"的打字机效果。
4. **`global sources`**：生成器里要修改外层变量 `sources`，所以声明 global（闭包写外变量必须 global）。
5. 回答完把 `{role, content, sources}` 存进历史。

```python
"""知识图谱可视化页面：Pyvis 力导向图展示实体邻域子图。"""

import streamlit as st
import streamlit.components.v1 as components

st.header("🕸️ 知识图谱可视化")
st.caption("输入实体名称，展示其邻域子图（节点颜色按类型区分）")

    "Fangji": "#1890ff",    # 方剂-蓝
    "Symptom": "#faad14",   # 症状-黄

    "Effect": "#722ed1",    # 功效-紫
    "Disease": "#13c2c2",   # 疾病-青
}
LABEL_NAMES = {
    "Herb": "药材", "Fangji": "方剂", "Symptom": "症状",

if st.button("查询并渲染", type="primary") and entity_name.strip():
    try:
        from kg.neo4j_loader import get_driver

        driver = get_driver()
        with driver.session() as session:
            records = session.run(
                """
                MATCH (a {name: $name})-[r]-(b)
                RETURN labels(a)[0] AS alabel, a.name AS aname,
                       type(r) AS rel, labels(b)[0] AS blabel, b.name AS bname
                LIMIT 100
                """,
                name=entity_name.strip(),
            ).data()
        driver.close()

        if not records:
            st.warning("图谱中未找到该实体的关联数据，请先导入知识图谱。")
            st.stop()

        from pyvis.network import Network

        net = Network(height="600px", width="100%", directed=True)
        added = set()
        for r in records:
            for label, name in ((r["alabel"], r["aname"]), (r["blabel"], r["bname"])):
                if name not in added:
                    net.add_node(
                        name, label=f"{name}\n({LABEL_NAMES.get(label, label)})",
                        color=LABEL_COLORS.get(label, "#999999"),
                    )
                    added.add(name)
            net.add_edge(r["aname"], r["bname"], title=r["rel"], label=r["rel"])

        html_path = "graph_viz.html"
        net.write_html(html_path)
        with open(html_path, "r", encoding="utf-8") as f:
            components.html(f.read(), height=640, scrolling=True)

        st.success(f"共渲染 {len(added)} 个节点、{len(records)} 条关系")
    except Exception as e:
        st.error(f"图谱查询失败，请确认 Neo4j 已启动：{e}")
```

**逐段讲解**：

1. **`LABEL_COLORS` / `LABEL_NAMES`**：节点类型 → 颜色/中文名的映射，让图更直观（药材绿、方剂蓝…）。
2. **查询**：`MATCH (a {name: $name})-[r]-(b)` 直接查某个实体名（如"柴胡疏肝散"）的一跳邻居，`labels(...)[0]` 取节点标签。
   - 注意这里**没写死标签**（`(a {name:...})` 而非 `(a:Fangji {...})`），所以输入任何类型实体都能查。
   - `name=entity_name.strip()` 参数化传值（和第 8 步一致的安全习惯）。
3. **`if not records: st.warning(...); st.stop()`**：查不到数据时**提前终止**页面渲染（`st.stop` 是 Streamlit 的"到此为止"），而不是继续跑后面画图报错。
4. **Pyvis 画图**：
   - `Network(directed=True)`：有向力导向图。
   - `added` 集合去重节点，边用 `title`（悬停提示）和 `label` 显示关系类型。
   - `net.write_html("graph_viz.html")`：**生成那个 `graph_viz.html` 文件**（文件清单里说的"生成物"就在这产生）。
   - `components.html(...)`：把生成的 HTML 嵌进 Streamlit 页面显示。
5. **异常兜底**：`st.error` 提示"请确认 Neo4j 已启动"——前端也做友好容错。

2. **`st.session_state.draft`**：草稿存会话状态，供"预览编辑"和"生成配图"复用。
3. **`st.text_area`**：可编辑文本框——用户能**手动改文案**后再发布（半自动方案的核心：人工把关）。
4. **两列布局 `st.columns(2)`**：左列生成配图（`generate_card`）、右列发布指引。
5. **发布是"半自动"**：`st.code(...)` 展示文案（右上角有一键复制），配合指引文字让用户**手动去小红书粘贴发布**——这就是 README 说的"安全无封号"方案，和 `publish_agent.py` 里的自动化占位形成对照。

# 第 24 步：lib/bindings/utils.js —— 前端图谱交互脚本

> 可视化页生成的 `graph_viz.html` 会引用这个 JS，提供**节点高亮、过滤、选中**等交互。
> 它是纯前端脚本，不依赖后端，独立成步。核心思路：**选中一个节点，高亮它和它的邻居，淡化其余**。

```javascript
function neighbourhoodHighlight(params) {
  // console.log("in nieghbourhoodhighlight");
  allNodes = nodes.get({ returnType: "Object" });
  // originalNodes = JSON.parse(JSON.stringify(allNodes));
  // if something is selected:
  if (params.nodes.length > 0) {
    highlightActive = true;
    var i, j;
    var selectedNode = params.nodes[0];
    var degrees = 2;

    // mark all nodes as hard to read.
    for (let nodeId in allNodes) {
      // nodeColors[nodeId] = allNodes[nodeId].color;
      allNodes[nodeId].color = "rgba(200,200,200,0.5)";
      if (allNodes[nodeId].hiddenLabel === undefined) {
        allNodes[nodeId].hiddenLabel = allNodes[nodeId].label;
        allNodes[nodeId].label = undefined;
      }
    }
    var connectedNodes = network.getConnectedNodes(selectedNode);
    var allConnectedNodes = [];

    // get the second degree nodes
    for (i = 1; i < degrees; i++) {
      for (j = 0; j < connectedNodes.length; j++) {
        allConnectedNodes = allConnectedNodes.concat(
          network.getConnectedNodes(connectedNodes[j])
        );
      }
    }

    // all second degree nodes get a different color and their label back
    for (i = 0; i < allConnectedNodes.length; i++) {
      // allNodes[allConnectedNodes[i]].color = "pink";
      allNodes[allConnectedNodes[i]].color = "rgba(150,150,150,0.75)";
      if (allNodes[allConnectedNodes[i]].hiddenLabel !== undefined) {
        allNodes[allConnectedNodes[i]].label =
          allNodes[allConnectedNodes[i]].hiddenLabel;
        allNodes[allConnectedNodes[i]].hiddenLabel = undefined;
      }
    }

    // all first degree nodes get their own color and their label back
    for (i = 0; i < connectedNodes.length; i++) {
      // allNodes[connectedNodes[i]].color = undefined;
      allNodes[connectedNodes[i]].color = nodeColors[connectedNodes[i]];
      if (allNodes[connectedNodes[i]].hiddenLabel !== undefined) {
        allNodes[connectedNodes[i]].label =
          allNodes[connectedNodes[i]].hiddenLabel;
        allNodes[connectedNodes[i]].hiddenLabel = undefined;
      }
    }

    // the main node gets its own color and its label back.
    // allNodes[selectedNode].color = undefined;
    allNodes[selectedNode].color = nodeColors[selectedNode];
    if (allNodes[selectedNode].hiddenLabel !== undefined) {
      allNodes[selectedNode].label = allNodes[selectedNode].hiddenLabel;
      allNodes[selectedNode].hiddenLabel = undefined;
    }
  } else if (highlightActive === true) {
    // console.log("highlightActive was true");
    // reset all nodes
    for (let nodeId in allNodes) {
      // allNodes[nodeId].color = "purple";
      allNodes[nodeId].color = nodeColors[nodeId];
      // delete allNodes[nodeId].color;
      if (allNodes[nodeId].hiddenLabel !== undefined) {
        allNodes[nodeId].label = allNodes[nodeId].hiddenLabel;
        allNodes[nodeId].hiddenLabel = undefined;
      }
    }
    highlightActive = false;
  }

  // transform the object into an array
  var updateArray = [];
  if (params.nodes.length > 0) {
    for (let nodeId in allNodes) {
      if (allNodes.hasOwnProperty(nodeId)) {
        // console.log(allNodes[nodeId]);
        updateArray.push(allNodes[nodeId]);
      }
    }
    nodes.update(updateArray);
  } else {
    // console.log("Nothing was selected");
    for (let nodeId in allNodes) {
      if (allNodes.hasOwnProperty(nodeId)) {
        // console.log(allNodes[nodeId]);
        // allNodes[nodeId].color = {};
        updateArray.push(allNodes[nodeId]);
      }
    }
    nodes.update(updateArray);
  }
}

function filterHighlight(params) {
  allNodes = nodes.get({ returnType: "Object" });
  // if something is selected:
  if (params.nodes.length > 0) {
    filterActive = true;
    let selectedNodes = params.nodes;

    // hiding all nodes and saving the label
    for (let nodeId in allNodes) {
      allNodes[nodeId].hidden = true;
      if (allNodes[nodeId].savedLabel === undefined) {
        allNodes[nodeId].savedLabel = allNodes[nodeId].label;
        allNodes[nodeId].label = undefined;
      }
    }

    for (let i=0; i < selectedNodes.length; i++) {
      allNodes[selectedNodes[i]].hidden = false;
      if (allNodes[selectedNodes[i]].savedLabel !== undefined) {
        allNodes[selectedNodes[i]].label = allNodes[selectedNodes[i]].savedLabel;
        allNodes[selectedNodes[i]].savedLabel = undefined;
      }
    }

  } else if (filterActive === true) {
    // reset all nodes
    for (let nodeId in allNodes) {
      allNodes[nodeId].hidden = false;
      if (allNodes[nodeId].savedLabel !== undefined) {
        allNodes[nodeId].label = allNodes[nodeId].savedLabel;
        allNodes[nodeId].savedLabel = undefined;
      }
    }
    filterActive = false;
  }

  // transform the object into an array
  var updateArray = [];
  if (params.nodes.length > 0) {
    for (let nodeId in allNodes) {
      if (allNodes.hasOwnProperty(nodeId)) {
        updateArray.push(allNodes[nodeId]);
      }
    }
    nodes.update(updateArray);
  } else {
    for (let nodeId in allNodes) {
      if (allNodes.hasOwnProperty(nodeId)) {
        updateArray.push(allNodes[nodeId]);
      }
    }
    nodes.update(updateArray);
  }
}

function selectNode(nodes) {
  network.selectNodes(nodes);
  neighbourhoodHighlight({ nodes: nodes });
  return nodes;
}

function selectNodes(nodes) {
  network.selectNodes(nodes);
  filterHighlight({nodes: nodes});
  return nodes;
}

function highlightFilter(filter) {
  let selectedNodes = []
  let selectedProp = filter['property']
  if (filter['item'] === 'node') {
    let allNodes = nodes.get({ returnType: "Object" });
    for (let nodeId in allNodes) {
      if (allNodes[nodeId][selectedProp] && filter['value'].includes((allNodes[nodeId][selectedProp]).toString())) {
        selectedNodes.push(nodeId)
      }
    }
  }
  else if (filter['item'] === 'edge'){
    let allEdges = edges.get({returnType: 'object'});
    // check if the selected property exists for selected edge and select the nodes connected to the edge
    for (let edge in allEdges) {
      if (allEdges[edge][selectedProp] && filter['value'].includes((allEdges[edge][selectedProp]).toString())) {
        selectedNodes.push(allEdges[edge]['from'])
        selectedNodes.push(allEdges[edge]['to'])
      }
    }
  }
  selectNodes(selectedNodes)
}
```

**逐段讲解**：

1. **`neighbourhoodHighlight`（邻域高亮）**：
   - 选中节点时：把所有节点染成半透明灰 + 隐藏标签 → 找出**一度邻居**（`getConnectedNodes`）和**二度邻居** → 一度邻居恢复原色+标签，选中的主节点恢复原色+标签。
   - 取消选中（`params.nodes.length === 0`）：把所有节点**复位**到原始颜色/标签。
   - 核心技巧：`hiddenLabel` 临时存标签、再恢复，避免"高亮时丢了原始标签"。
2. **`filterHighlight`（过滤）**：选中时把**非选中节点隐藏**（`hidden = true`），只留选中的；取消时全部恢复。
3. **`selectNode` / `selectNodes`**：两个对外入口，分别触发"高亮"和"过滤"。
4. **`highlightFilter`（按属性过滤）**：
   - 传入 `{item: 'node'|'edge', property: ..., value: [...]}`，按属性值筛选节点或边。
   - 比如"找出所有 label 为 Herb 的节点"。
5. **整体理解**：这套代码本质是 Pyvis 生成图的**交互增强层**——让用户在力导向图上点选、高亮、过滤。注意里面大量 `// console.log` 注释是开发调试遗留，不影响功能。

> 注：`lib/tom-select/*`、`lib/vis-9.1.2/*` 是**第三方前端库**（下拉选择框、vis-network 网络图），属于 vendor 依赖，非本项目代码，故不展开。

**逐段讲解**：

2. **装 Tesseract + 中文包**：对应 `ocr_parser.py` 的 `chi_sim` 依赖——**容器里得有 OCR 引擎**，否则古籍扫描件解析会失败。
3. **Docker 层缓存优化**（经典技巧）：
   - 先 `COPY requirements.txt .` 再 `RUN pip install`，最后才 `COPY . .`。
   - 因为 Docker 按层缓存，**只要 requirements.txt 不变，依赖层就能复用**，改代码重构建时不用重新装依赖（省几分钟）。
4. **`-i 清华源`**：国内装依赖提速（呼应 README 和 AGENTS.md 的"国内镜像"要求）。
5. **`CMD` 启动 Streamlit**：`--server.address=0.0.0.0` 让容器外部能访问。

## deploy/docker-compose.yml —— 一键编排

```yaml
# 中医药知识图谱智能问答系统 - 一键部署
# 使用方式: docker-compose up -d
services:
  neo4j:
    image: neo4j:5
    container_name: tcm-neo4j
    ports:
      - "7474:7474"   # 浏览器控制台
      - "7687:7687"   # Bolt 协议
    environment:
      NEO4J_AUTH: ${NEO4J_USER:-neo4j}/${NEO4J_PASSWORD:-neo4j}
    volumes:
      - neo4j_data:/data
    healthcheck:
      test: ["CMD", "cypher-shell", "-u", "${NEO4J_USER:-neo4j}",
             "-p", "${NEO4J_PASSWORD:-neo4j}", "RETURN 1"]
      interval: 10s
      timeout: 5s
      retries: 10

  app:
    build:
      context: ..
      dockerfile: Dockerfile
    container_name: tcm-app
    ports:
      - "8501:8501"
    env_file:
      - ../.env
    environment:
      NEO4J_URI: bolt://neo4j:7687
      MODELSCOPE_CACHE: /app/models
    volumes:
      - model_cache:/app/models    # 国产模型权重缓存（GTE/COROM），重启不重复下载
      - faiss_index:/app/index
    depends_on:
      neo4j:
        condition: service_healthy

volumes:
  neo4j_data:
  model_cache:
  faiss_index:
```

**逐段讲解**：

1. **两个服务**：`neo4j`（图数据库）+ `app`（应用）。`docker-compose up -d` 一起拉起。
2. **`neo4j` 服务**：
   - 端口 `7474`（浏览器控制台）、`7687`（Bolt 协议，程序连接用——对应 `.env` 里的 `bolt://`）。
   - `NEO4J_AUTH` 用 `${NEO4J_USER:-neo4j}` 语法：**取环境变量，没设则用默认值 `neo4j`**。
   - `healthcheck`：用 `cypher-shell ... RETURN 1` 探活，每 10 秒试一次，最多 10 次。
3. **`app` 服务**：
   - `build.context: ..`：构建上下文指向项目根（因为 Dockerfile 在根目录）。
   - `env_file: ../.env`：把 `.env` 注入容器（密钥来源）。
   - **`NEO4J_URI: bolt://neo4j:7687` 覆盖了 .env 里的 `localhost`**——容器内访问另一个容器要用**服务名 `neo4j`** 而非 `localhost`（Docker 网络机制）。
   - `volumes`：挂载 `model_cache` 和 `faiss_index` 两个卷，**模型权重和向量索引重启不丢、不用重新下载/重建**。
4. **`depends_on: condition: service_healthy`**：app 等 neo4j **健康**了才启动（配合上面的 healthcheck）——避免"应用启动了但数据库还没就绪"的竞态。
5. **三个命名卷**：`neo4j_data`（图数据）、`model_cache`（模型）、`faiss_index`（索引）都持久化。
